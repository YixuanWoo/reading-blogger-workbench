## 一、这是什么

一个把「一条口播录音」做成「一支成片视频」的**本地工作台**（Windows WPF 桌面程序）。

它的立场很明确：**你是剪辑师，AI 是助手，最终决定权在你手上**。
所以整个流水线在每一个会自动动刀的地方，都留了人工审核节点——
AI 剪错的代价是「你多点一下」，而不是「素材废了」。

核心工作流是一条七环流水线（详见维护说明第二节）：

```
① 转写 → ② 粗剪决策 → ③ 人工审核 → ④ 分镜设计 → ⑤ 渲染 → ⑥ 组接成片 → ⑦（可选）导出 XML
```

## 三、★ 维护守则（改动前必读）

### 3.1 三条不可违反的架构铁律

1. **`LiteCut.Core` 不许依赖 Windows。**
   它是为将来跨平台留的净.layer。不许 `using System.Windows`，不许引用 NAudio/WPF，
   不许硬编码 `C:\` 开头的路径。要读写音频，`IAudioDecoder` 让界面层去实现。

2. **成片画面规格统一，且必须有文字锚点。**
   统一横屏 1920×1080 · 30fps；背景图用**各项目自己的**
   `项目\<项目名>\素材\公共素材\grid-bg-deep-blue-grid.jpg`
   （立项时自动从软件夹 `素材模板\` 复制，每个项目自包含）；
   元素卡片式叠在底图上、四周留白、浅色字。
   ★「不要字幕」= **不要底部同步字幕条**，**不等于画面里不要文字**——
   每个镜头必须有关键词/标题/数字等文字锚点，零文字镜头 = 废镜头
   （2026-09-30 曾按错口径渲染，219 镜全废）。

3. **音频优先，画面去匹配声音。**
   你的精剪输出就是完成稿，音频**全程零处理**（不拉伸、不变速、不改电平）。
   画面设计时长 = 对应音频段时长 + 几帧安全余量；组接时裁掉余量对齐。

### 3.2 修改流程（每次改动都要走）

```
改代码
  → dotnet build 必须 0 警告 0 错误
  → 在 文档/更新日志.md 追加一条记录（改了什么 / 动了哪些文件 / 为什么）
  → 如果改了任一方向 outdated 的行为约定，同步改 文档/维护说明.md
  → 需要发布则跑 build.ps1，产物自动落到 D:\工作台
```

### 3.3 「交给 Agent」相关约定

工作台通过**任务包文件**与 Agent（WorkBuddy 会话）通信，用户说「领任务」即认包：

| 任务包 `<项目>/stages/...` | 含义 `kind` | 回包写哪里 |
|---|---|---|
| `03-shot/agent-request.json` | `shot` 分镜设计 | 同目录 `agent-response.json` |
| `04-render/agent-request.json` | `render` 整批渲染 | 同目录 `agent-response.json` |
| `04-render/agent-reshoot.json` | `reshoot` 单镜重渲 | `agent-reshoot-response.json` |

自动唤醒由 `工具/agent-bridge/bridge.js`（本地 18765 端口）经 CodeBuddy Gateway 完成。
★ **不要以「没有外部 AI API Key」为由排除 AI 方案** —— 走网关即可，用户无需任何手动操作。

### 3.4 渲染三铁律（HyperFrames 渲染时）

1. 必须显式传并发数（默认 auto 会开一堆 Chrome 顶爆内存）。
2. **渲染期间一个文件都别删**（宿主删前备份会灌爆 C 盘）。
3. 单镜失败必须重试 ≥3 次、间隔 ~20s（Edge 会瞬时启动失败）。
   渲染前确认 **C 盘剩余 ≥ 2GB**。

## 四、快速上手

### 编译（验证改动是否正确）

```powershell
C:\Program Files\dotnet\dotnet.exe build 工作台\工作台.csproj -c Release
# 目标：0 个警告 0 个错误
```

### 打包发布（产物自动进「程序」文件夹）

```powershell
.\build.ps1
# 产物：D:\工作台\工作台.exe（单文件 ~140MB，双击即用）
```

去 lief → 运行 `D:\工作台\启动.bat`（或双击 `工作台.exe`）。

> 注：程序集名仍是 `LiteCut`（csproj 的 `<AssemblyName>`，代码里的标识，不动）；
> `build.ps1` 在打包末尾把交付文件名改成中文 `工作台.exe`，两者不冲突。

### Visual Studio 打开

双击 `工作台.sln`。

### 纯源码状态说明

工程刻意保持「不含 bin/obj」——它们是编译产物，`build` 时会重新生成。
觉得工程很大时，先确认是不是没清 bin/obj。
