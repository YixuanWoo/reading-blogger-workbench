T-16 · 拆镜头 / 合镜头

一个会「静默出错」的坑

拆镜头这件事本身没问题，问题出在拆完之后 —— 从拆点往后，每个镜头都会读到隔壁镜头的画面。 而且它什么都不报。

坑 · 拆一镜，后面画面全错位
险 · 不报错，成片直接错
解 · 分档提醒 + 自动改名 + 撤销

1问题：一个镜号，同时干三份活

把 51 个镜头想成 51 个座位，每个座位挂一个号。这个号，同时是三样东西 ——

①

座位号

它在第几位。分镜表从上往下的顺序，靠它。

拆完会跟着变
②

身份牌

Agent 写的分镜设计、渲染任务、单镜重渲，都靠这个号找对镜子。

拆完不会变
③

文件名

shot_007.mp4、shot_007.body.html、t_007.jpg

拆完不会变
你拆一镜 = 在队里插一个人 → 后面全体往后挤一位。
但只有第①个身份变了。磁盘上那 51 个文件一个都没动，文件里的编号也不会自己改。 （代码里 ReindexAndReload() 只做了一件事：改内存顺序）

3最要命的是：它不报错

你点「出片」，软件照常跑完，吐给你一个整片错位的成片。
没有弹窗、没有红字、没有任何提示 —— 可能发出去之后才发现。

附带问题 · 合并时设计会消失

合并两镜，被合并那一镜的分镜设计（画面、动效、配图）直接没了，连提示都没有。

附带问题 · 拆完设计「超范围」

原镜的设计还在，但它已经写超了 —— 动效写着 0-3s / 3-6s / 6-9s 三段，现在只剩 3.2 秒。界面毫无感知。

4怎么修（1）：拆合随便拆，交棒才提醒

核心态度：不拦你，只说清代价，然后帮你收拾干净。

你定的规矩：所有交接只走「应用到下游」。 没点它，下游读的还是上一版镜头表 —— 拆合只改「草稿」，产物不可能错位。

分镜页现在恰恰没有这个按钮（现状是拆完 / 合完立刻落盘），T-16 要补的就是它。
补上之后：拆合 → 只改草稿；点「应用到下游」→ 才重排 + 改名 + 标「待重渲」。

★ 那个"静默错位"的坑，不是靠"改名做得好"来解的，是靠"压根还没交接"来解的。

水位判的是「这一次交接有多贵」——拆的时候一律不打扰，交棒那一刻才按档提醒。

L0
刚切完口播，还没做分镜设计 你说的「语义确定之前随便拆」就是这一档
拆合不弹框 · 交接无代价
L1
分镜设计已经做好了 拆合时轻问一句设计怎么处理；交接时轻确认
拆合轻问设计 · 交接轻确认
L2
画面已经渲染了 交接时要动磁盘上的文件名
🔴 交接时红字：要改 44 个文件
自动帮你改，出错能回滚
L3
成片都已经出了 同 L2，另外成片作废了
🔴 同上 + 提醒「成片要重拼」
打个比方 —— 装修房子：
毛坯随便砸墙（L0）　·　刚刷完漆再砸，问你一句（L1）　·　家具进场了要挪 44 件，我们帮你挪（L2）　·　都住进去了还得重新摆一遍（L3）

关键：砸墙这个动作本身随便做（改草稿），"挪家具"是交钥匙那一刻才发生的事（点交接）。

5怎么修（2）：原来那些设计怎么办

拆成两镜

原来那一镜 → 设计保留，但它现在只对得上前半段 → 挂「待复核」
新出来的那一镜 → 空着 → 挂「待补设计」

像把一篇文章从中间劈开：前半段还是原文，后半段得重写。

另一种选择：两镜都清空、交给 Agent 重新设计 —— 弹框里就这两个选项（"按时间自动切分"是伪选项，已删）。

合成一镜

两镜的设计 → 首尾拼起来（合起来内容确实就是这两段连着）→ 挂「待复核」
不再直接丢掉

像把两篇文章接上：接上正好是全文，但接缝要看一眼。

★ 这些「待复核」标记，只有你点「确认无误」才会消失，系统不自动清 —— 自动清等于系统替你判断，正是现在出毛病的原因。

6怎么修（3）：给每个视频贴张防伪标签

是什么

每个渲染好的视频旁边记一张小卡片，写着：
「我是第 7 镜，我的台词 / 画面 / 动效 / 时长是这些。」

干嘛用

搬完文件对一下卡片，就知道有没有搬错。光把文件名改对还不够 —— 得确认这个视频确实是这一镜的。

像快递单号：包裹换了位置，单号对得上，才算没送错。

7镜号到底该怎么办 —— 你说的两个方案

先说结论：这两个方案不是二选一，它们是同一件事的两半。
合起来用才对 —— 顺推当主干，ID 当内核。

镜号 —— 会变

管「排第几」「叫什么名字」：
① 界面显示「第 7 镜」
② 文件名 shot_007.mp4
③ Agent 提示词里的镜头表
④ 组接页的块序
⑤ 你嘴上说的「第 7 镜重渲一下」

ID —— 永不变

管「这份设计 / 这个产物是谁的」：
① 分镜设计归谁
② 渲染产物归谁
③ 留痕文件（Agent 回包 / 提示词）
④ 撤销
⑤ 对账：搬完文件核对有没有搬错

一句话记住：镜号是「座位号」，ID 是「身份证」。 座位会换，身份证不换 —— 点名用座位号，找人对身份证。
那为什么只有镜号顺推还不够？　没有 ID 的顺推 = 蒙着眼睛搬 44 个文件， 搬错了也不知道（这正是现在的病）。
有了 ID 才敢搬：能算清单、能校验、能回滚、能撤销。

于是剩下一个真岔路要你选：shot_007.mp4 这个名字，跟不跟镜号走？

甲 · 文件名跟着改名　推荐

拆一镜 → 后面 44 个文件跟着改名
目录里一眼对上镜号　★★★
下游（渲染页 / 组接页 / 提示词）零改动
风险：搬到一半崩了 → 靠「计划 + 校验 + 回滚」压住

乙 · 文件名按 ID，磁盘永不动

拆一镜 → 零磁盘操作（不会半途而废）
目录看不懂（"第 9 镜的产物怎么叫 shot_007？"）　★
下游 4 处要改（命名 / 解析 / 提示词 / 组接块序）
老项目要一次性把 51 个文件改名

推荐甲。下游零改动 + 目录可读 + 搬文件的风险有 ID 兜底。
乙唯一的优势是「零磁盘风险」，代价是人看不懂目录 —— 而这个软件的日常维护， 恰恰经常靠人翻目录。
★ 先做 ID 的好处是给未来留了门：哪天你觉得搬文件烦，切乙只需改「命名 + 解析」这一层， 数据层一行不用动。
补一刀：ID「藏后台」✅ 但「只活在上游」❌
产物按镜号命名（对）、ID 不进文件名（对）—— 但 ID 得跟着产物一路走到渲染页， 否则没人会发现「产物过期」：
① 51 镜渲好 磁盘：shot_001..051.mp4（旧镜头表的产物） ② 回分镜页拆第 3 镜 镜头表变成 52 镜 ③ 磁盘一个文件没动 shot_004.mp4 还是「旧第 4 镜」的画面 可第 4 位现在坐的是「原第 3 镜的后半」 ④ 直接去出片 → 整片错位，而且不报错
★ 「改名」和「重渲」是两件事：拆一镜后，除拆点那一两镜，其余 40 多镜画面 一模一样（第 5 位装的就是原第 4 镜的画面）—— 所以只需改个名字（毫秒级）， 不必重渲（十几分钟 + 电费）。你说的"按镜号渲染"要对，得"全部重渲"才行。
一句话：ID 不上门牌，但入住要刷它。藏后台 ≠ 只在上游。

不管选甲还是乙，算法骨架是同一套：

拆 #k 成两镜： ① 原镜 k ID 不变，位置不变，标「待复核」 ② 新镜插入 k+1 分配新 ID，设计字段全空，标「待补设计」 ③ k+1 之后的镜头 镜号 +1，ID 全都不变 ④ 算搬迁计划 [ {id:"s07", from:"shot_007.mp4", to:"shot_008.mp4"}, … ] ⑤ 执行 按「安全顺序」搬（见下面细节 1） ⑥ 校验 按 ID + 指纹逐条核对，确认没搬错 ⑦ 收尾 全成功 → 删计划；任一失败 → 按计划反向回滚，恢复原状 合并 #k, #k+1： 保留靠前那个的 ID；后一个的 ID 记进 mergedInto 后作废 k 之后的镜号 −1，其余同上

★ 三个最容易翻车的地方（这才是"算法"的肉）：

1

改名得倒着来

从前往后搬会自己盖自己：

❌ 前 → 后 shot_008 → shot_009 └ 盖掉了还没搬的 shot_009，原文件永久没了 ✅ 后 → 前 shot_051 → shot_052 shot_050 → shot_051 … shot_008 → shot_009

规则：镜号变大 → 从大号往小号；变小 → 反着来。图省事就统一走 .tmp 中转。

2

ID 里别带镜号

你举例的 123a 这种不行 —— 镜号一变， 123 就成了撒谎的遗迹，看 ID 反而误导。

用跟位置无关的号： s01 s02 s03 … 血缘另记一个字段： 新镜记 fromId = "s07" 老镜记 mergedInto = "s12"

这样「它是谁」和「它从哪来」是两件事，各自都不会撒谎。

3

只改"驱动流程"的，不动"留痕"的

要改：shot-NNN.* 产物、shot-overrides.json、render-tasks.json

一个字不改：agent-response.json、prompt.md —— 那是"当时发生了什么"的记录，改了就是篡改历史。

留痕文件里带上 ID 就够：镜号后来变了，靠 ID 照样对得上。

老项目怎么办？（比如 思辨与立场 那 51 镜）
补发一次 ID 就行 —— 按当前顺序 1..51 各发一个号，写进 shotlist.json。 不改任何文件名、不动任何产物，纯加字段，做完永不回头。

8UI 长什么样

两个框，各管各的 —— 拆合时只问设计，点交接时才摊代价：

框 A · 把 #7 拆成两镜？
#7 前半 3.2s · 设计保留 待复核
#8 后半 4.2s · 设计为空 待补设计
原来的设计怎么办？（两个选项）
保留原镜设计 彻底清空重设计
取消 拆分

框 A 里为什么不谈产物

拆完下游一个字都不动 —— 没点交接，下游读的还是上一版镜头表。

所以"44 个视频要改名"放这里是吓唬人，那是交钥匙那一刻的事。

① 直接把结果摆出来，不让人自己脑补
② 只留两个真需要你选的（保留 / 清空）
③ 原先那个「按时间自动切分」是伪选项，已删 —— 句子自带时间，拆镜头必然按时间切，那是拆分的定义不是选项

框 B · 点「应用到下游」时 —— 这里才摊代价：

把这份镜头表交给下游？（52 镜）
⚠ 重排 52 个镜号（#4 起往后移一位）
⚠ 改名 48 个渲染产物（shot_004…051 → shot_005…052）
⚠ 48 个镜头标「待重渲」
☐ 我知道从第 4 镜往后的画面会失效
取消 交接

框 B 才是"分档"的地方

L0　一行轻提示（直接过）
L1　轻确认（只几镜设计待复核）
L2　强确认：红字 + 产物数 + 勾选才让点
L3　同 L2 + 「成片需重新组接」

拆之后 —— 卡片挂徽章，顶部出汇总，旁边有后悔药：

卡片上的状态徽章

待复核 待补设计 待渲染 待重渲 已就绪 ✎ 边界被调过

「✎」和设计状态是两件事，不合并 —— 一个管「重切分别覆盖我」，一个管「设计要复核」。
