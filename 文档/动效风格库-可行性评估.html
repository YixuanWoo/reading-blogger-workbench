一、先把那篇文章说人话 它到底干了什么

作者做了两件事，一件是「炫技片」，一件是「干活片」：

  • 炫技片：一个卡通形象穿过 23 种画风 —— 洞穴壁画 → 古埃及壁画 → 北斋巨浪 → 莫奈日本桥 → 蒙克《呐喊》→ 8-bit 像素夜……每进一幅画，他就换成那幅画的画风，还跟画里的东西互动（在巨浪底下缩头、在桥上打水漂）。
  • 干活片：加了 8 种 YouTube 常见的解说风格（白板、Vox、Kurzgesagt、3Blue1Brown、发布会 UI、财经图表、故事、动态文字）。同一段口播，换个风格就是另一种感觉，可以单独配一段插进正在剪的片子里。

关键在这句（作者原话的意思）：场景是代码画的，配乐也是代码一个音一个音合成的（没用一个采样）。整支片子里，只有「他自己的卡通形象」是调用生图模型（gpt-image）出的帧 —— 其余全部是代码算出来的。

他把它沉淀成了一个 skill（huashu-art-motion），里面有：几十张「艺术风格卡」（洞穴壁画、敦煌、浮世绘、印象派、梵高、蒙克、达利、霍珀、波普、吉卜力、新海诚、蒸汽波……每张卡里写清配色、笔触、动作怎么做、以及这风格目前的短板）+ 拆参考视频的方法 + 配乐怎么跟画面卡节拍 + 自检程序（跑一遍挑出静止帧、异常跳变，再让一个没参与制作的 agent 只看成片挑毛病）。

三、为什么「算法算出来」这条路对你特别合适 而不是 AI 生成

  • 符合你已有的规矩：工作台早就明文「动效全部用网页技术实现（HTML/CSS/GSAP）：位移、缩放、描边画出、逐字出现、数字滚动、粒子聚合/消散、Ken Burns」，并且「禁止实拍航拍、真人出镜、三维建模」。用代码画场景，正好是这条规矩的自然延伸 —— 不需要破规矩，是规矩本来就想指的方向。
  • 每一帧都是数学：贝塞尔缓动、SVG 路径、噪声函数、粒子受力、透视变换 —— 全部可推导、可复现。同一个参数，永远得到同一帧。
  • 和你「内容指纹」判据天生一对：工作台靠「产物认 ID + 内容指纹」判断哪个镜头待重渲。算法动画是确定性的 → 指纹判据继续成立；AI 生成是随机的 → 每次重跑都不一样，你连「这条要不要重渲」都判不了。这一点上，你选的这条路比文章那套更稳。
  • 零生成费用、零版权风险：不调生图/生视频模型 → 没有图片 token、没有生成额度、没有素材版权，也不存在「审不出是谁画的」。
  • 代价只有一条：纯算法画不出写实的人和物 —— 贝塞尔和噪声函数能画出几何化/线条化的小人（圆头方身、剪影、抽象符号），画不出"像照片里那个人"。
    但这一条有解，而且不必向「生图出帧」投降：角色形象一次性生成、之后骨骼动画全用代码写 —— 这是你本轮定下的边界，详见下面「补一节 · 关于角色」。信息图、图表、白板、抽象动效完全不需要角色；角色戏走「资产复用」这条路，比生图出帧更稳、更省、可重渲。

补一节 · 关于角色：一次生成、永久复用 2026-10-16 你补充的边界 —— 修正本报告原结论

你的原话（这就是规矩）：「我也不是不愿意用生成模型生成角色，但生成的角色要能够复用。就是一次生成，以后骨骼动画都要代码写。我允许 AI 生成复用资产，但不允许生成一次性视频。一次性视频太奢侈了。」

这条规矩比「干脆不用 AI」高明 —— 它划出了一条干净的分界线：
静态的、可枚举的、能反复调用的 → 允许交给生成模型；动态的、一次性的、逐帧算出来的 → 必须代码写。

按这条线：可以生成 —— 角色形象、贴图、纹理、背景画、图标、音色采样。
不可以生成 —— 任何「这一支片子专用的画面序列」，以及任何「同一句话每次跑出来都不一样」的东西。

技术上怎么落地：把「角色」和「动作」拆成两件事

这套管线在 3D 游戏和动画行业是标准做法（建模一次 → 绑定骨骼 → 动画由代码/关键帧驱动），你只是用 HTML/SVG/canvas 把它重写一遍。关键在「资产」与「动作」必须是两个独立文件 —— 前者生成一次就冻结，后者每次做片现写。

① 一次生成
AI 生图 · 只需一次
出一张角色形象（正面站姿、透明底，必要时补侧面/背面）。这一步用生图模型，花一次钱，产出一个可长期持有的「资产」。
② 一次性拆件
工具/人工 · 只需一次
切成部件：头 / 躯干 / 上臂 / 前臂 / 手 / 大腿 / 小腿 / 脚（+ 眼、嘴、发）。每个部件一张透明底 PNG。这就是「角色」的最终形态 —— 之后永不再生成。
③ 代码绑骨架
写一次 · 所有角色共用
一份 rig.json 描述骨架：谁是谁的孩子、关节在哪（pivot）、每段多长。本质是自己写一个极简版 Spine。驱动器与角色解耦：换角色只换配置，代码一个字不动。
④ 代码写动作
做片时唯一要写的一层
GSAP 驱动各关节的角度/位移：走路、指、点头、挥手 = 一组参数曲线。同一组参数，永远得到同一帧。这就是「骨骼动画全用代码写」，也是你「内容指纹」判据能继续成立的原因。
⑤ 逐帧渲染
HyperFrames 照旧 seek 截屏。引擎一个字都不用改。现有 bodies\shot_xxx.body.html 里加一层 <image> / <use> 引用部件即可。

「拆件」这一步怎么走 —— 三条路线，代价不同

路线怎么做代价 / 短板

★ 建议起步		 生成一张完整形象 → 抠图 + 切成部件。你机器上已有抠图/图像处理能力可用。 切件是一次性人工活（几十个部件）；肘/膝/肩要补「关节遮挡圆片」防露缝。但只做一次。

账：为什么「一次性视频」奢侈，「复用资产」便宜

同一个角色，做 10 支片子一次性视频（你不允许）一次生成资产（你定的规矩）
第 1 支生成一段专属画面生成 1 张形象 + 切一次件（一次性）
第 2 支再生成一次，和上次完全不同代码调用同一资产（几十行）
第 10 支第 10 次生成还是那几十行
能不能验内容指纹✗ 每次都不一样，「要不要重渲」判不了✓ 同参数必得同帧
改一句台词那一整段作废重来只改台词，角色的形象与动作一点不动
版权审查每一段都要单独审审一次，长期持有
本质差别买到的是画面 —— 只能用一次买到的是资产 —— 能长出新东西

顺带一句：这条规矩不只适用于角色。背景画、纹理、贴图、图标、甚至音色采样，全都适用同一把尺子 —— 静态可复用就允许生成，动态逐帧就必须代码算。

动手前必须先实测的三件事（都是真风险，不是吓唬）

高
图片加载时序 —— 可能截到空白帧
逐帧截图是按毫秒抢的，<image> 从磁盘读的那一瞬可能还没解码完，截出来是空白。挡法：部件 base64 内联进 html（无外部请求），或渲染前等图片 load 完成再启动时间轴。这条不实测不能开工。
中
单帧性能 —— 比纯矢量慢
位图部件比 SVG 路径吃内存，部件多 + 滤镜多的镜头更明显。挡法：重滤镜烘成静态图，动画只动 transform/opacity；先拿一个 5 秒镜头测出「每镜秒数」，再决定允许多少部件。
低
关节质量 —— 弯到一定角度会露缝
这是所有 2D 骨骼动画的固有毛病，不是你的锅。挡法：标准解法 —— 在肘/膝/肩压一个「关节遮挡圆片」，或者拆件时把部件画到略微超出关节一点点。

对现有体系的影响：新增一层「角色资产库」，不动任何已有机制。

  • 落点：跟已有的 素材模板\ 同一套逻辑（立项时复制进项目），建议每个角色一个文件夹：parts\*.png（部件）+ rig.json（骨架）+ 动作\*.json（动作配方）。
  • 与判据的关系：资产进「ID + 内容指纹」体系 —— 资产变了，用它的镜头自动判「待重渲」。这一步不需要新机制，现在这套已经能装下。
  • 不需要动的：分镜字段、组接层、渲染任务包结构、gen_shots.py 骨架、VisualStandard.cs。期三（风格卡）之外的额外账，基本为零。

一句话收尾：这条路不是"算法不如生图的退让方案"，而是比「生图出帧」更高级的一档 —— 生图出帧的人拿到的是一段画面，你拿到的是一个能用十年的角色。前者用一次就没了，后者越用越顺手（动作库、表情库都能往上叠）。

回本点：做一支片子，就够建一次库

一次性把「风格卡 20~30 张 + 动效配方 30 个 + 装订文档」建起来，估 ≈ 25 万 token（含反复调试回环）—— 正好等于你现在做一支 3.3 分钟片子的开销。

五、四个风险，以及怎么挡 诚实列出来

最大
渲染耗时可能翻几倍
HyperFrames 是逐帧截屏（每帧都要让浏览器真渲染一次）。整帧代码画 + 粒子 + 噪点滤镜（feTurbulence）会让单帧变慢，再乘以 30fps × 时长。这是唯一可能「技术可行但用起来痛」的点。
挡法：① 重滤镜（纸纹、颗粒、笔触）一次性烘成静态 PNG，动画只动 transform / opacity（GPU 友好）；② 上承下来先拿一个 5 秒镜头实测，出「每镜秒数」的账，再决定风格卡允许多重的滤镜；③ 逐镜渲染本来就是你的规矩，慢也只慢在单镜，不阻塞。
中
要动到「分镜 → 任务包 → 组接」三层
现在的分镜数据里没有「这一镜用哪种风格」这个字段（字段集实测：Id / Index / 起止秒 / Text / Description / Motion / Image / ImageFile / Edited / DesignStale）。加一个 Style 字段就要按你那条铁律两头一起改：ShotPrompt（分镜提示词要教它选卡）、RenderPrompt（任务包要带上这张卡）、组接层（不改，但指纹要复算）。
挡法：把它当一个新的 T 项正规走一遍，别顺手改。而且第一期完全可以不加字段（见下面的路径）—— 先用「整支片子一个风格」跑通，验证清楚了再开逐镜选卡。

《视觉规范.md》是画面唯一真源，得先改它
规范第一节现在写死了「底图统一铺深蓝网格、禁止任何图片铺满全屏」。不先改规范就做新画面，等于每次任务包都自带一条和它打架的指令，Agent 会摇摆。
挡法：好消息是改一处就全局生效（规范每次组装任务包时重读、不缓存，这是 V1.11.3 就做好的）。把「深蓝网格」从唯一底图降级为风格族里的第一张卡（品牌识别保留），再写「底图由代码生成，其调性以本节色板为准」。这是好事 —— 等于把「更丰富的动效」制度化，而不是靠我每次临场发挥。
低
配乐通路要从头开
文章里「代码一个音一个音合成」在技术上零难度（正弦/方波/噪声 + 包络，Python 或 ffmpeg 都能做，零 AI、零版权）。但你工作台的音轨通路现在是「口播重建 + 插片原声」，没有 BGM/音效这一路（《视觉规范》§二13 已经把它标成「标准预留、待通路实现」）。
挡法：这一段是独立可选的第二期，跟前三期不耦合。先解决画面，音乐最后再说。

六、落地路径 四期 + 一期（角色资产），从「马上就能看到差别」到「完整形态」

期一
背景不再是那张固定图 —— 这一步就能解决你说的「单调」
把渲染脚手架骨架里的那一行 background-image: url("bg.jpg") 换成一层可参数化的程序化背景（渐变天空 / 星尘 / 海面细浪 / 纸纹 / 透视网格……一个「背景族」，七八种起步）。同一支片子里，每镜可以换一种背景，深蓝网格作为「品牌卡」保留在其中。
为什么先做这个：改动面最小（只动 gen_shots.py 骨架 + 几个背景类），不碰分镜字段、不碰组接层、不碰提示词结构，当天就能渲一镜看效果。而且它直接命中你的抱怨 —— 单调的根源就是「每镜同一张底图」。
★ 期一必须捆一件事：把「风格标识」写进内容指纹（RenderManifest.FingerprintOf()）—— 否则改了风格界面还报"已就绪"，详见第八节。
期二
动效配方库：把「怎么写」变成「怎么叫」
现在的公共库 _lib.js 只有 6 个函数（in / out / draw / seq / dim / tl）。扩到 30 来个可参数化配方：描边生长、粒子聚合、数字滚动、遮罩揭示、视差推拉、故障抖动、逐字弹入、波形律动、路径跟随、光环扩散……
效果：Agent 从「写 6,000 字」变成「调 LIB.motion('粒子聚合', {...})」—— 这一步是 token 下降的主要来源。
期三
风格卡库：对照文章的「几十张卡 + 8 种解说风格」
每张卡 = 配色板 + 背景族 + 笔触做法 + 默认动效配方 + 已知短板（文章最聪明的一笔：每张卡都记下「这个风格现在哪里做不好」，下次接着改）。
建议先备 12~15 张就够用一支片子：解说实用向（白板、信息图、财经图表、发布会 UI、时间轴、地图/路径、对比分屏、数字看板）+ 审美向（水墨、敦煌、浮世绘、粗粝纸感、蒸汽波、极简几何）。分镜时给每个镜头挂一张卡。（到这一步才需要加分镜字段）
期三点五
角色资产：一次生成、永久复用（本节新增的一期）
风格卡库里加一族「角色卡」—— 每张卡 = 一个角色的形象资产（部件 PNG）+ 骨架定义 rig.json + 一组动作配方（走/指/点头/挥手）。
顺序上它排在期三之后，但那个 5 秒实测要提前做：拿一个 5 秒镜头，塞进一张位图部件 + 代码驱动关节，量两件事 —— ① 会不会截到空白帧（图加载时序）② 单帧多花多少毫秒。这两个数出来，才谈得上选拆件路线（B 整图切件 / C 矢量化 / A 分部件生成 / D 3D）。
为什么值得单独开一期：它是唯一能让画面出现「人」的路径，而且一旦建好，之后每一支片子的成本几乎为零 —— 你买到的是资产，不是一个画面。
伴随项
算法质检：这一步省的钱最多
纯算法、零 token：用 ffmpeg + Python 逐帧差分，自动挑出①静止帧（画面超 5 秒没动，正是你《视觉规范》§二11 那条规矩）②异常跳变 ③元素越界/塌到角上 ④元素互相遮挡（§二14 那两批返工的理由）。跑完只把可疑镜推给人/模型看，而且抽帧图先降到 960×540 再看。
单看这一项，就把现在六成以上的 token 开销砍掉大半 —— 而且它是「一支片子不建风格库也能立刻做」的独立收益。
期四
程序化配乐/音效（可选，独立）
代码合成 BGM 与音效，随风格卡换乐器/调式；需要新开音轨通路并处理闪避（ducking）。零 AI、零版权。不着急，前面三期跑顺了再做。

七、待你拍板 四个选择，一句话就行

我不动手，等你点头。顺序上我建议 ①→②，③ 单独想清楚，④ 排在期三之后

  1. 要不要先做「期一 + 伴随项」？（换掉固定底图 + 算法质检）—— 这两件改动面最小、收益最直接：前者解决你说的单调，后者立刻把 token 降下来。不用碰分镜字段，不用改组接层。
  2. 风格是「整支片子一种」还是「逐镜挑」？我建议先整支一种（零字段改动，先看清效果和耗时），跑顺了再开逐镜选卡。逐镜选卡更丰富，但要动分镜字段 + 三处提示词。
  3. 「深蓝网格」是保留成品牌卡，还是可以退场？我建议保留成风格族里的第一张卡（观众认得出是你的片子），但不再唯一。
  4. 角色资产这条线，什么时候动？（「补一节」新增）我建议排在期三风格卡之后，但先做那个 5 秒实测（图片加载时序 + 单帧耗时）—— 因为实测结论会决定拆件路线的选择（B/C/A/D）。
    另需你定一处：角色资产库存哪 —— D:\HyperFrames\assets\（跨项目共享，像模板库）还是 工作台\素材模板\（跟现有立项复制机制统一）？我倾向后者。

八、改造后你在工作台里怎么用 你几乎不用学新东西 —— 落点已经存在了

先回答最关键的疑问：是的，改造完你在工作台里就能用，而且你日常的操作路径一个字都不用变。

你现在走的是「分镜 → 生成渲染任务包 → 交给 Agent 渲染」这条链。改造只是换掉这条链的输入：
从「一张固定底图 ＋ 每次让 AI 从零写 6,000 字代码」→ 换成「一张风格卡 ＋ 调配方函数」。你点的地方几乎没变。

落点在哪：分镜页顶部那个「换背景图…」，升级成「画面风格 ▾」

现在分镜页顶部就有一行规格显示 + 两个按钮（换背景图… / 打开背景图）。这就是风格选择的天然落点 —— 不用新开页面、不用动导航菜单（`NavTree.cs` 一行都不用改）。改造后这一行变成：

成片规格：1920×1080 · 30fps · 3 帧安全尾　风格：深蓝网格 · 经典　[画面风格 ▾] [预览] [打开风格卡]

「是不是得给我添加风格选项？」—— 不是写死几个，是库是文件夹，选项自己长出来

一张风格卡 = 一个文件
D:\HyperFrames\styles\<卡名>.json —— 里面写：配色板 / 背景族 / 笔触做法 / 默认动效配方 / 已知短板。
加一张 = 丢个文件
往文件夹里丢一个 json，下拉列表里自动多一行。不用改程序、不用重新编译、不用找我。和现有 D:\HyperFrames\templates\ 的登记表逻辑完全同族 —— 你已经在用这套了，只是现在那本登记表只有 4 行。

一次完整操作长什么样（五步）

步骤在哪做什么
1分镜页 · 顶部点「画面风格 ▾」，从列表挑一张（列表按项目类型分组，比如解说实用向 / 审美向）
2分镜页 · 顶部点「预览」看一眼效果（可选，跑一个 3 秒样例镜就够了 —— 省 token 的关键）
3分镜页 · 底部点「应用到下游」← 闸门！不点，下游读的还是旧风格
4渲染页「生成渲染任务包」→「交给 Agent 渲染（整批）」
5渲染页看状态灯逐格变绿（这套实时刷新已经有了，8 秒一轮）

第 3 步是这套系统一贯的规矩（「上游改完必须点一次应用到下游」）。风格也必须走这道闸门 —— 否则会出现"我明明换了风格，渲染出来还是旧的"这种最难查的错。

★ 必须同时补的一件事（本轮翻代码新发现的真漏洞，不改会咬人）

现在的「待重渲」判据只看镜头内容：文案 / 画面构思 / 动效 / 配图 / 时长（RenderManifest.FingerprintOf()）—— 没算底图，也没算任何规格。

意思是：你今天点「换背景图」，界面不会把任何镜头标成「待重渲」。底图换了，状态灯却还是绿的。

风格一旦变成可选项，这个洞会立刻咬人 —— 你换了风格、界面说"已就绪"、出片还是旧的。
所以期一必须同时做：把「风格标识」写进指纹。这跟 R-17 / R-19 那条判据铁律是同一族毛病：判「要不要往下走」要看磁盘事实，不能信内存里那个乐观的绿标记。

好消息：render-spec.json 里已经有一处写"这次用的到底是哪张图"（Background 字段），把它升级成"哪张风格卡"+ 进指纹，改动面小。

改一次风格，代价是多少

  • 改风格 = 全部镜头待重渲（因为底图和笔触进了每一镜的骨架）。这是"换一套视觉重来一版"的代价，一次而已 —— 不是说每支片子都付。
  • 点「应用到下游」的那一刻，系统会按水位告诉你：改多少文件、多少镜待重渲（这套摊代价的机制已经在跑了，2026-10-01 就有）。
  • 真正天天省下来的是第二件：因为风格由卡决定、动效由配方库决定，Agent 每镜要写的代码从 6,000 字变成几十行 → 这就是账本里那 75%~80% 的来源。
