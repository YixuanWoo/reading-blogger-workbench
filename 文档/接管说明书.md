### 2.1 两层分工（一句话）

- **`LiteCut.Core`** = 所有"跟界面无关"的计算：转写稿解析、静音检测、重复句检测、镜头切分、时间轴碰撞、音频拼接、契约 JSON 读写。**不带 `-windows`**，谁的代码里出现 `System.Windows` 或 NAudio，编译就红——这是故意的。
- **`工作台`** = 界面与交互：窗口、页面、录音台、渲染调度、Agent 桥接、设置。

### 2.2 Core 里的关键文件（改算法先看这里）

| 文件 | 管什么 |
|---|---|
| `Contracts\*` + `Contracts\ContractJson.cs` | 五份契约（transcript / cutplan / shotplan / pipelinejob / finalscript）与统一 JSON 读写（**无 BOM UTF-8 的唯一来源**） |
| `Engine\TranscriptImporter.cs` | 转写稿导入，认「标准契约」和「原始 ASR（subtitles）」两种格式 |

## 3. 构建与运行

### 3.1 前置条件

> `%LOCALAPPDATA%` 下的 8.x SDK，这样两台机器结果一致。

### 3.2 编译（不发布）

```powershell

```

### 3.3 发布成成品（会覆盖正在用的 exe）

```powershell
cd D:\工作台工程\工作台
.\build.ps1
```

它做三件事：`build` → `publish`（自包含单文件）→ 把 `LiteCut.exe` 改名成 `工作台.exe` 并覆盖到 `D:\工作台`，
最后**只在缺** `D:\工作台\视觉规范.md` 时补种出厂底稿（**绝不覆盖用户改过的那份**）。

### 3.4 运行

双击 `D:\工作台\启动.bat`（内部就一句 `start "" "%~dp0工作台.exe"`，窗口标题「翊瑄的工作台」）。
数据目录 `D:\工作台` 是**程序所在目录**——exe 挪走就找不到 `项目\` 了，别挪。

### 3.5 换一台干净机器怎么复现

1. 装 .NET SDK 8 → 2. `git clone https://github.com/YixuanWoo/reading-blogger-workbench.git` → 3. `dotnet build .\工作台\工作台.csproj -c Release` → 4. `.\build.ps1`（产物落 `D:\工作台`）→ 5. 双击 `启动.bat`。
渲染/组接要额外准备 `D:\HyperFrames`；不装也能开界面、能走前四环。

## 5. 禁区（一根指头都别碰）

1. **`D:\工作台\项目\`** —— 真实作品，含成片、素材、录音。任何测试、截图、回归都不许在这里做。

4. **`D:\工作台\素材模板\`** —— 出厂素材种子。
5. **`D:\HyperFrames\`** —— 渲染引擎本体（含 ffmpeg），删了渲染全废。
6. **别用 `build.ps1` 做"验证"** —— 它会把产物覆盖到正在运行的程序夹。验证一律用 `dotnet build` / `.\健康检查.ps1`。

## 6. ★ 明文规矩：真实数据只读，测试只用虚拟数据

> 这一节是硬规矩，不是建议。写在这里是为了让后面每一单都看得见。

**① 真实数据只读。**
`D:\工作台\项目\*`、`%APPDATA%\翊瑄的工作台\*`、`D:\工作台\视觉规范.md`、`D:\工作台\素材模板\*`
只能**读**。不许写、不许改名、不许移动、不许"顺手清理"。需要看结构就 `Get-Content`，需要统计就只读遍历。

**② 测试、截图、回归一律用虚拟数据。**
- 用仓库自带的 `测试素材\`（样例音频等），或
- 在 `%TEMP%` 下自建临时目录造样本，用完删掉。
- 需要跑界面的手工验证：在一个**假项目**上做（`%TEMP%\…\项目\<假名>\project.json`），不许开真实项目。
- 自检程序（`工具\自检`）本身也只写 `%TEMP%`：它把契约文件写到 `%TEMP%\workbench-selfcheck-<guid>\`，跑完自删。

**③ 每次交付都要自证"没碰真数据"。**
做法（本单就是这样做的，可直接抄）：

```powershell
# 交付前
Get-ChildItem 'D:\工作台\项目' -Recurse -File | Get-FileHash -Algorithm SHA256
# 连同 LastWriteTimeUtc.Ticks 一起存成 JSON；交付后再跑一次，逐条比对 —— 必须 100% 一致
```

对比结果写进交付报告：**文件数、一致数、不一致数**。不一致就是没做到，不许含糊过去。

**④ 需要改数据格式时**：先整目录备份到 `_删除备份\<时间戳>\`，且**保留旧格式读取路径**，报告里写清迁移与回滚方法。

## 7. 回滚办法

| 场景 | 怎么退 |
|---|---|
| 代码改坏了（未发布） | `git -C D:\工作台工程\工作台 revert <commit>`；或 `git checkout -- <文件>` 丢掉未提交改动 |

## 9. 每次更新 / 每周体检怎么跑

**每次更新（必做）**
1. `cd D:\工作台工程\工作台`
2. `.\健康检查.ps1` → 必须「结论：通过」、退出码 0
3. 改 `文档\更新日志.md` 记一笔；改了行为口径就同步 `文档\维护说明.md`
4. 关掉工作台 → `.\build.ps1`（要发布才做）
5. `git add` 指定文件 → `git commit` → `git push origin main`
6. 报告里贴：健康检查输出摘要、commit 号、真假数据一致数

**每周体检（照着念）**
```powershell
cd D:\工作台工程\工作台
.\健康检查.ps1                 # 编译 0 警告 0 错误 + 自检全过
git status                     # 有没有人把改动作业留在本地没提交
git log --oneline -10          # 这周改了什么
gh run list --limit 5          # 没有 CI，这行为空；看到有跑说明有人擅自加了流水线
```
额外看一眼：`D:\工作台\logs\` 最近有没有大量报错、`%LOCALAPPDATA%\翊瑄的工作台\crash.log` 有没有新增崩溃。

**体检结果怎么读（别自己把自己吓一跳）**
- `[过]` / `[败]` = **门禁项**，计入失败、决定退出码（0 过 / 1 不过）。
- `[注意]` = **提示项**（视觉规范在位、真实数据目录在位、仓库工作区干净），**只提醒，不计入失败、不影响退出码**。
  日志末尾固定有一行「判据」写着这句，看到 `[注意]` 别当成红。
- 仓库工作区那项标 `[注意]` 只说明「有改动没提交」，提交完再跑就是 `[过] 干净`。
