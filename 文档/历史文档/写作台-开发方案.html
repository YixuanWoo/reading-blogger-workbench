一、放在哪

问题：写作台该放在项目内，还是全局菜单？
项目内 · 流水线的第 0 步
判据只有一条 —— 稿子属于「某一支片」，还是属于「我」？
稿子存在项目\思辨与立场\script.md，跟着片子走 → 项目内。
放全局就会造出没有归属的孤儿稿，那恰恰是它最该避免的状态。
为什么不插在 1粗剪 和 2 精剪 中间？
因为它不是流水线的一环，是 ① 的上游
稿子 → transcript.json → 粗剪。插中间会暗示"剪完才开始写稿"，那是倒着。
所以它排在最前面，编号 0；现有 1~5 一步不���、不重编号——重编号会让老项目的截图和记忆全部对不上。

三、核对现状时挖出的三个坑

坑 1　默认落点写死了，打开老项目会"稿子丢了"
现在 DefaultProjectId => StepCut 是常量。加了写作台后，打开《思辨与立场》这种已做完的老项目， 落地却弹到空的写作台，用户以为稿子没了。
修法：改成按立项模式分流 —— 新项目（文稿驱动）落写作台，老项目（录音驱动）仍然落粗剪。 老档案反序列化出来天然是recording，零改动。
坑 2　ScriptText 这个名字已经被占了
实测 ProjectModel.cs:166 已有 ShotPart.ScriptText，注释写着"降级用的文案稿"。 写作台如果也叫这个名字，将来两个"稿子"字段必然打架。
修法：三者职责定死 —— 稿源（script.md，人写的原文）、带时间的稿（transcript.json，下游吃这个）、 成片口播稿（ScriptText，派生物）。新代码一律不许叫 ScriptText。
坑 3　01-transcript 现在是空目录，别写成"已支持"
实测 项目\AI时代读书的价值\stages\01-transcript\ 里 0 个文件—— 转写稿一直是外部 Agent 交付的，粗剪页那颗"复制转写提示词"就是给它的任务书。
不影响方案（写作台是生成方之一），但文档里不能写"工作台已支持 transcript.json"。

四、写作台长什么样

编辑器选型
不引入 AvalonEdit / Monaco / WebView2
工作台要的不是"一个完整 md 编辑器"，是"能把稿子切成段落节点的编辑器"。
存盘是 md（你能在 Obsidian 里写），编辑是卡片流（与分镜页同一套心智）→ 零新依赖。
与 Obsidian 的关系是单向：打开读一次 / 保存整份重写 /开着时你在 Obsidian 改了不管。

五、最值钱的一处：下游一行都不用改

老路
整段录音→外包ASR

新路
稿子+分段录音
→
transcript.json

②③④⑤ 零改动
为什么这条值这么多
时间戳从"猜的"变成"累加出来的"
老路的Start/End 是 ASR 猜的 →会漂（那条血泪规矩实测差56 秒）。
新路是片段边界累加 → 零误差，而且稿子零损耗、不用外包。
所以这不是"给流水线加两个前置环节"，是换掉一个数据源，其余全不动。
