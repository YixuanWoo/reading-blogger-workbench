## 第一节 · 整体架构（先看这张图）

```
┌────────────────────────────────────────────────────────────┐
│  工作台 (WPF 客户端)                    ← 界面、交互、设备 IO  │
│  只做：画 UI、读写文件、调 ffmpeg、同 Agent 通信             │
└───────────────────────┬────────────────────────────────────┘
                        │ 引用（单向，Core 绝不反向依赖界面）
                        ▼
┌────────────────────────────────────────────────────────────┐
│  LiteCut.Core (net8.0 类库)          ← ★ 纯计算，跨平台      │
│  禁止：System.Windows / NAudio / 硬编码盘符路径              │
│  内容：契约 + 算法 + ffmpeg 编排 + 时间轴逻辑                │
└───────────────────────┬────────────────────────────────────┘
                        │ 进程调用
                        ▼
┌────────────────────────────────────────────────────────────┐
│  外部                                                        │
│  ffmpeg/ffprobe │ HyperFrames 渲染引擎 │ agent-bridge │ Agent│
└────────────────────────────────────────────────────────────┘
```

### 为什么这么切成两层

一句话：**为了有一天能搬到 Mac。**

`LiteCut.Core` 里一个 Windows API 都不许有——解码不在 Core（由界面层实现 `IAudioDecoder` 喂 `PcmData` 进来），
播放器不在 Core，路径不写死。将来换平台，只换「界面 + 解码器」这两个壳，**算法一行不动**。

这不是洁癖：《步 >0Core 层那 33 个文件里，绝大多数是踩过坑才长成的算术 -
每一条都附了"上次为什么错"的注释。能在新平台直接复用它们，等于把踩过的坑整个搬过去。

### 依赖规则（不可违反）

| 方向 | 允许吗 | 说明 |
|---|---|---|
| WPF → Core | ✅ | 正常调用 |
| Core → WPF | ❌ | 一旦出现，跨平台资格作废 |
| Core → Windows 专属库（NAudio/WPF/注册表） | ❌ | 用接口把依赖甩给界面层 |
| 任何层 → `C:\` 硬编码 | ⚠️ | 只允许出现在配置**默认值**里，且必须能被覆盖 |

## 第二节 · 运行逻辑（七环流水线）

流水线每一环的产物都**落盘成 JSON**，环与环之间靠文件交接，不靠内存。
好处：中途关掉工作台、电脑重启，回来还能接着跑；出问题时能回滚到上一环重来。

| 环 | 名称 | 输入 → 处理 → 输出 | 谁干活 |
|---|---|---|---|
| ① | 转写 | 音频 → whisper/外部 Agent → `<项目>\stages\01-transcript\transcript.json` | 外部 Agent（粗剪页「**复制转写提示词**」那颗按钮就是给它的任务书，V1.1.8） |
| ② | 粗剪决策 | 音频(PcmData) + 转写稿? + **稿子(script.md)?** → 三层分析（波形/文本/**对稿**）→ `cutplan.json` | **`AutoCutEngine`（纯算法，不用 AI）**<br>★ V1.12.5 / T-28：多一层「对稿」——有 `script.md` 时拿它当标准答案对录音，重录判得更准 |
| ③ | **人工审核** | 用户在波形上勾选/否决 ← 流水线到此停下等你 | 用户 |
| ④ | 分镜设计 | 成片口播稿 → 切成语义块 → 设计每块画面 | `ShotSplitter` 初切 + Agent 设计 |
| ⑤ | 渲染 | 逐块 HTML/CSS/GSAP → 逐块 MP4 | **HyperFrames**（外部引擎） |
| ⑥ | 组接 | 逐块 MP4 + 按决策重建的音轨 → 成片 MP4 | **`FFmpegAssembler`** |
| ⑦ | 导出 XML | （可选）生成 FCP7 XML 交达芬奇 | `FFmpegExporter` 旁路 |

### 〇→① 上游：写作台（V1.11.0）

写作台是① 转写的**上游**（`script.md` → `transcript.json` → 粗剪），摆在流水线最前面、编号 `0`。

★ **V1.11.0 起它是一整篇 Markdown，不再是"回车切段"**：

| | 旧（V1.10.x） | 新（V1.11.0） |
|---|---|---|
| 文档本质 | 回车切出的段落块 `ScriptBlock[]` | **一整篇 Markdown 原文**（一个字符串） |
| 左栏 | 回车块列表（s01 + 字数/时长） | **文章目录 TOC**（按 `#~######` 标题自动生成，按层级缩进） |
| 回车 | 切段（=新段落节点） | **只是换行**，不产生结构 |
| Markdown | 完全不识别 | **实时解析渲染**（右上角「展开预览」按需打开） |
| 录音/重录 | 挂在段落块上（永久ID/audio/待重录） | **已整体删除**（录音是期二的事，届时另做） |

★ **模块独立**：写作台整体收敛在 `Workbench\WritingDesk\`，内部只认「路径 + 宿主接口」
（`IWritingDeskHost` 拿 .md 路径/发状态/问确认，`IWritingDeskPage` 供主窗口调保存/未保存判断），
不依赖 `Project` / `WorkbenchWindow`。将来独立成写作软件，整个文件夹直接带走。

★ **保存管线不变**：稿子仍走唯一入口（顶栏「保存项目」/ Ctrl+S / 20 秒自动保存），
由 `WorkbenchWindow` 通过 `IWritingDeskPage.Save()` 一并落盘。

### ② 粗剪：双轨设计与它的三个安全闸门

这是整套系统最核心的设计。两条轨**各自独立、可降级**：

```
波形轨（永远跑，零误伤）
  第1层 静音/气口   → SilenceDetector（看 dB 均值，不看峰值）
  第2层 波形级重复   → RepeatDetector（比包络形状，不需要文字）
文本轨（有转写稿才跑）
  第3层 填充词      → FillerLexicon + SpeechIssueDetector
  第4层 半截重说
  第5层 词级口吃
  第6层 整句重复
对稿（有 script.md 才跑，V1.12.5 / T-28）
  第7层 重录        → ScriptAligner（"稿上这句只写一次"+两段互相像 → 保后不保前）
  副产品 偏差清单    → 稿上有没录 / 原本没写你说了（只报告，不动手）
```

★ **没有转写稿，波形轨照样跑完全流程**——这是产品硬要求，不是"技术上能跑"。
whisper 没装、被卸载、换引擎、将来 Mac 上没有，任何一种情况都不能让流程停摆。

★ **对稿是"加一层信息"，不是"换一套算法"**：它对不上就整体不算数（`Used=false`），
粗剪原样退回上面那两轨。下限 = 加它之前，上限 = 把"废片重录"准确挑出来。
它的产出**照样**要走下面三道闸门（不另开特例）。

三道闸门保证「宁可少剪，不可错剪」：

1. **校验**：转写稿进来先过 `TranscriptAligner`。时间码对不上（Agent 编的可能外表合法、每句都错），直接**拒绝并降级**，不照错数据下刀。
2. **定点**：文字说"大概第 12.3 秒"±0.2s 误差 → 拿波形在附近找真正安静的瞬间当刀口。**文字负责删什么，波形负责在哪下刀。**
3. **背书**：下刀前检查这段是否真有人声。文字说"这里说了嗯"、波形说"这里是静音" → 不动手。

### ③→④ 交接：`FinalScript` 为什么是关键

旧的错法：拿**文案稿**（你动笔写的）+ 按字数占比摊时间。两个毛病——
你写稿和嘴上实际说的往往不是一回事；字数占比≈时间占比是假设语速均匀，剪得越多偏得越多。

正确做法：
```
转写稿（每词有源素材时间码）
  ∩ 精剪决策（每块引用源素材哪一段）
  = 保留下来的词，按【块在成片中的先后】串起来
```
★ **顺序必须按块在成片里的先后，不能按源时间扫**——精剪允许挪块（把后面那句挪到前面讲），
按源时间排会得到一篇"读着通顺、画面全配错地方"的稿子，而且是最难发现的那种错。

### ④→⑤ 交接：分镜页的「应用到下游」闸门（V1.1.0）

★ **一条贯穿全系统的铁律**：**所有环节的交接只走「应用到下游」**。
上游改完（粗剪 / 精剪 / 分镜）必须点一次，下游才开始按新版本走、才标「待重渲」等状态。**没点 = 下游读的还是上一版。**

- 粗剪页 ✅ / 精剪页 ✅ 早已是真闸门（共用 `ActiveDecision` + `DecisionSource`，顶栏「下游使用：…」由 `RefreshDecisionIndicator()` 刷）。
- **④ 分镜页（V1.1.0 补齐）** ✅：`_s.ShotDraft`（编辑中）⇄ `_s.Shots`（**恒等于已交接版**）。
  **下游 ⑤⑥ 继续只读 `_s.Shots` → 下游代码零改动**。闸门 = `CommitShotDraft()`。
- 为什么要这么设计：**拆 / 合镜头曾会让"一个镜号同时扛顺序、身份、文件名"三件事**。
  一旦"改了内存没改磁盘"，产物就会**静默错位且不报错**。
  ★ 这个坑**不是靠迁移做得好来解，是靠"还没交接"从根上解**——没交接，磁盘上就压根没错位。

**永久 ID（`s01…`）**：与位置无关、只增不减、**永不复用**、**不进文件名**，但必须活到渲染页（`render-manifest.json` 的键）。
重切分按**源区间**继承身份（`RangeKey` 量化到 0.01s）——**边界没变 = 同一镜**，ID / 设计 / 配图原样保留。

**交接那一刻会发生什么（`Plan` → `Execute`）**：
1. 按新顺序重排镜号（`Index`），同时把磁盘上 `shot_NNN.mp4/html/…` **跟着改名**（**双缓冲**：先全 `→.tmp` 再落正式名，绝不自己覆盖自己）；
2. 被合并掉的镜头其产物先挪进 `渲染产物\_已废弃\`；
3. 按**内容指纹**标「待重渲」；全部落 `shotlist.json` + `reindex-log-<时间>.json`（可据此**单步撤销**）。

### ★ 插片：分镜表里"没有口播"的那一段（V1.10.7）

**它是什么**：用户手动插入的一段镜头（`ShotRow.IsInsert = true`）——
**画面照常写分镜**（跟普通镜头一模一样），但**成片里这一段是静音的**，时长由用户自己定，
视频素材**可选**（不用素材就是一段纯静音画面）。

**两条轴必须同时 +N**（这是全部设计的根）：

| 轴 | 来源 | 插片怎么落 |
|---|---|---|
| 画面 | 分镜表 `_s.Shots` 按 `DurationSec` 累加 | 插片就是表里的一行 → 天然 +N |
| 音轨 | 精剪时间轴 `TimelineSnapshot` | ★ **组接那一刻**补一段等长静音（`Step4ExportView.AddAudioForInserts()`）；★ **V1.10.15**：插片若勾了「素材原声」，这一段改取**该镜渲染产物的音轨**（`FilmSegment.VideoAudioPath`），不再补静音 |

`Precheck` 强制两轴相等（差 0.5s 拒绝出片）→ **这一段占位是必需项，不是可选项**。

★ **为什么不能往精剪时间轴里塞"空白块"**：时间轴会被当成口播保留区间去和转写稿求交
→ 口播稿凭空多出一句；且**预览听着静音、导出却是真的人声**（导出按源区间 `atrim` 裁真录音）。

★ **V1.10.15 · 插片「素材原声」**：素材自带的声音默认**不放出来**（老规矩不变）；
分镜卡上勾了「素材原声」+ 音量之后，全链路三处一起变 ——
① 渲染提示词按 `audioVolume`（线性倍数）写 `data-volume` 而不是写死 0；
② `render_tasks.json` 的 `silent` 变 false、多出 `insertAudio/audioVolumeDb/audioVolume`；
③ 组接层那一段改接产物音轨。
**插片原声只能从渲染产物里抠** —— 成片音轨是从**原录音**重建的，而插片不属于这次录音，
它在原录音里没有对应位置。**产物不在磁盘上就退回静音并日志报警**（绝不让音轨短一截）。
所以插片只写**下游**（分镜表），上游一概不动。

**三条时长规则**：① 新插入 = 3.0s（记住上次）；② 选了素材才自动改素材全长，
且**只在用户没亲手改过时**（`DurationPinned`）；③ 视频比设定短 → **定格最后一帧**（不循环）。

**边界**：插片源区间 = `-1`（0 会撞 `RangeKey(0,0)`）；重切分**保留**插片（按原位置插回）；
插片**不能合并不能拆**。

### ⑤→⑥ 组接：为什么必须做「整帧对齐」

渲染器出片时长只能是整帧整数倍（30fps，1帧=33.3ms）。设计 8.325s 的块实际出 8.333s。
单块差 0~33ms 看着没事，**51 块累起来就是 0.744 秒**，画面渐进性地慢过口播。

解法：**不动视频**（重编码掉画质），把每块的音频按该块**实测时长**微拉伸（`asetrate` + `aresample`），
使音画在每块边界重新对齐、误差不累积。单块拉伸 0.1~0.6%，人耳听不出。
★ **别用 `atempo`**——它对千分之几的微小变速几乎不生效（实测 tempo=0.99904 输出仍是原长）。

> ⚠️ 同类累积误差在口播稿上踩过一次：漏算句间气口 → 219 句累差 16.8 秒。
> 「每段都很小」不等于「整体不重要」。

## 第四节 · ★ LiteCut.Core 逐文件详解（着重）

### 4.1 【契约层 `Contracts\`】— AI 和程序看同一份文件

> 这一层全是数据类，几乎没有逻辑。但它们决定了「AI 说什么」和「程序读什么」能否对上。

| 文件 | 干什么 | 关键设计 |
|---|---|---|
| **`CutPlan.cs`** ★枢纽 | 粗剪决策。**全流程最重要的一份格式**，承载 AI 判断 + 用户审核 + 下游输入三件事 | 只描述「源侧」不描述「时间轴」——时间轴位置由 `ComputeTimeline()` 纯算术算出。**AI 只管剪哪儿，排哪儿交给程序**。`Validate()` 会查重叠/越界/剪光。`suggestions` 存「检测到了但不敢自动剪」的候选，等用户点头。<br>★ **V1.12.5 / T-28** 增 `script`（`ScriptCheck` + `ScriptDeviation`）＝「对稿」结果。**别和 `transcript` 混**：`transcript` 管"稿子配不配得上这条音频"（物料自检），`script` 管"录音说没说稿子上的话"（内容比对） |
| **`FinalScript.cs`** | 成片口播稿。剪完后观众**实际会听到**的那篇稿子，每句带成片时间码 | `IsEstimate` 标记是不是「没转写稿只能按字数摊」的估算——界面必须写明。<br>`Truncated` 表示少说了内容；★ 判据是「被剪掉的秒数」而不是「句范围被块边界切到」（后者会误报 61%） |
| `ShotPlan.cs` | 镜头设计。音频轴上一段配一个视觉呈现 | 镜头互相独立→可并行让多个 Agent 设计（实测 3 并发加速 3.0×）。`renderDurationSec` 小于设计值时组接要补帧 |
| `Transcript.cs` | 转写稿。句级(阅读) + **词级(最小可切单元)** 双层粒度 | 词级时间码是刚需：刀要在字与字之间下，不能切在词中间 |
| `PipelineJob.cs` | 流水线任务状态。**给工作台自己用**，不是给 AI 的 | 落盘是为了"关掉再开知道刚才干到哪"。`IsStuck()` 检测超时——Agent 侧是串行队列+3并发上限，卡住会占着名额导致后面全被限流 |
| `ContractJson.cs` | 契约统一读写入口。**所有序列化必须走这里** | 三件套：中文不转义（否则 AI 读 `\u4F60` 费劲）、枚举写小驼峰字符串、null 不落盘。`LoadSchema()` 读内嵌 json 塞给 Agent 当硬约束 |

### 4.2 【公共基础 `Engine\`】— 所有算法的地基

| 文件 | 干什么 | 关键设计 |
|---|---|---|
| **`PcmData.cs`** | 解码后的音频数据（跨平台） | Core 不引用 NAudio，解码由界面层实现 `IAudioDecoder` 喂进来。**固定单声道**——说话人只有一个，立体声是冗余，且合单声道后能量计算不会因左右相位差而抖动 |
| **`Envelope.cs`** | 音量包络：把几百万采样点压成几千个数 | 每 5ms 算一个 RMS。保留「重音/停顿/句长」的节奏、丢掉相位细节。**同一句重说一遍，节拍几乎一样** → 这正是"没转写也能去重"的原理 |
| **`CharTimeMap.cs`** | 「第几个字」↔「第几秒」的翻译桥 | 算法在文字上思考，剪刀要落在时间上。★ 归一化的坑：删标点后"第 i 个字"≠"原文第 i 个字符"，解法是**逐词归一化**——每个词自己归一化，词内字平均分摊该词时长 |

### 4.3 【波形层 `Engine\`】— 永远会跑的那一轨

| 文件 | 干什么 | 关键设计 / 踩过的坑 |
|---|---|---|
| **`SilenceDetector.cs`** | 找「哪里没声音」。人工剪掉的 237 秒里有 165 秒是这िए一类 | ★★ **看这一段全程的平均音量（mean），绝不能看瞬时峰值（max）**。真实案例：25.10 秒真静音，mean=-60dB 但一个底噪尖峰 max=-26dB，用 max 会得出"这段有人声"的荒谬结论——第一版就栽这，误伤率 91.7%，改 mean 后是 0%。用 dB 而非振幅是因为人耳感知是对数的 |
| **`RepeatDetector.cs`** | 找「明显重复」，**不需要转写** | 比包络形状：明显重复近乎复制粘贴，相关系数能到 0.9+，不同话很难超 0.86。<br>★ 剪哪一个的规则：B 不比 A 短 → A 是废版（剪 A，最常见）；B 明显比 A 短 → 可能是修辞重复，**不自动剪，只标注** |
| **`FillerLexicon.cs`** | 中文口水词词表 | ★ 分两级：**一级纯语气词**（嗯/啊/呃，没意思，敢自动删，误伤代价≈0）；**二级话语标记**（就是/然后/这个/其实，有语法作用甚至实词义，如"他就是杜甫"删了句子散架）→ **只标注不自动删**。这层二分避免了"一刀切把'然后'全删、读起来像电报"的翻车。一级词挑得很保守：宁可漏手补一刀，不可误删一个字 |

### 4.4 【文本层 `Engine\`】— 有转写稿才跑

| 文件 | 干什么 | 关键设计 |
|---|---|---|
| **`TranscriptImporter.cs`** | 把外部转写稿读进来 | ★ 为什么不能直接反序列化：外部 Agent **格式偏差是常态不是意外**（字段叫 `w` 不叫 `text`、编号叫 `id`、时间截写成字符串…）。更糟的是失败很隐蔽——JSON 合法、反序列化"成功"但 Segments 是空的，程序不报错、语义层等于没启用。这里做三步：先按标准读 → 失败/读空走宽松解析映射别名 → 无论哪条路都"清洗"一遍，并且**每步都记进 Notes**（"我替你改了什么"必须能交代） |
| **`TranscriptAligner.cs`** | **这份稿子对不对得上这条音频？** | 为什么必须有：**时间码可能是编的**。大模型填 JSON 时不知道"第几句在第几秒"，但会填一个看起来合理的数字（比如按字数平摊到全片）。这种稿子格式合法、校验全过、读起来也对，唯独每句时间都错。拿它下刀 = 字幕错位、删掉旁边那句，且很难发现。<br>怎么验：**不用重跑转写**——手上有包络，看"这 3 秒到底有没有声音"即可。三级处理：对齐好→双轨；整体偏移→估算统一偏移量校正后再用；对得很差→**自动降级纯波形+明确告诉用户为什么** |
| **`TextSimilarity.cs`** | 两串中文有多像。四把尺子 | Dice(整体相似度) / Overlap(是不是被那句包住) / LcsRatio(讲同一件事) / PrefixLen(说到一半卡住重说)<br>★ **用字符 bigram 不用分词**——中文没空格，分词要挂词典（jieba），多一个依赖多一处崩的可能。"讲/的是/是唐/唐代"天然表达词边界；实测效果跟分词接近但零外部依赖（跨平台考虑：依赖越少越好） |
| **`SpeechIssueDetector.cs`** | 从文字里找「该剪的地方」 | 人工剪的 237 秒里，剩下的 72 秒废话就是这层要解决的四类：填充词 / 半截重说 / 词级口吃 / 整句重复。<br>★ ② 和 ③ 为什么要分开：② 发生在**两句之间**（有明显停顿）；③ 发生在**一句之内**（几乎没间隔，就是嘴瓢）。判据完全不同。<br>★ 贯穿全局的原则：**拿不准就标出来，不动手**。每个结果都带 `Confidence` + `AutoCut`，置信度没过阈值的照样出现在列表里但 `AutoCut=false` |
| **`TextCutOptions.cs`** | 语义层那几个旋钮 | 与 `AutoCutOptions` 是**并列**关系不是替代：有转写→两轨都跑；没转写→只跑波形，文案层对象不生效，不牵动波形层一行代码。<br>★ 每个检测项有**独立的 AutoCut 阈值**——四类问题的"拿不准程度"天差地别（半截重说几乎不会错，话语标记风险最高），用同一阈值会让保守的过度保守、激进的过度激进 |
| **`ScriptAligner.cs`** ★（V1.12.5 / T-28） | **对稿**：拿 `script.md` 当标准答案对录音 | ★ 粗剪不满意的**根因不是算法差、是信息不够**——它能发现"你说了两遍"，但分不清"说错重录"还是"有意重复"。翻一下稿子就知道：**稿上这句只写一次 → 前一遍是废片**。<br>做法：`ParseScript()` 洗 Markdown 成句（**一行一句为底**，行内按 。！？切）→ 单调 **DP** 对齐（每段录音归哪句稿子；支持一句配多段）→ 同一句配到多段时按"两段**互相像**"判重录、**保后不保前**。<br>★ RunScore 四项各管一件事：基础分（最像那段）/ 扎堆奖励（没它重录被漏）/ **夹带惩罚**（没它稿外发挥被吞）/ 破并列（稿子有两句很像时选"配给最像的那句"）。<br>★ 相似度 = `0.5·Dice + 0.35·LCS÷较长 + 0.15·字符集合重叠`——LCS 特意除以**较长**那句，防"两个字恰好出现"冒充高相似。<br>★ **永远降级**：对齐率 <0.50 或对齐句数 <3 → `Used=false`，什么都不动（最常见原因是"拿错稿子"）。偏差清单只**报告不动手**。 |

| 文件 | 干什么 | 关键设计 |
|---|---|---|
| **`AutoCutEngine.cs`** ★ | 把两轨合起来，产出 `CutPlan`。**流水线第②环本体** | 阶段 A 转写校验 → B 波形轨 → C 文本轨 → D 合并+总护栏 → E 铺满全片生成 Segments。<br>★ **V1.12.5 / T-28**：`Analyze()` 末尾多一个**可空** `scriptMarkdown`（不传＝老行为一字不变）。有稿子且对稿可信 → 重录改由 `ScriptAligner` 判（"稿上只写一次"比纯文本稳），`Detect(..., includeRetakes:false)` 不再跑纯文本重录；对稿产出的重录照样过**既有**的波形背书 + 总护栏，不另开特例。结果写进 `plan.Script`。<br>★ `MergeOverlaps` 里踩过坑：**合并时保留哪个 reason 有讲究**。第一版"保留先到的"，结果语义层正确识别的"半截重说"前面挨着一小段静音，一合并 reason 只剩 `silence`——用户看不到下面是重要语义判断。改成取**信息量更大**的那个（`ReasonPriority`：FalseStart/Retake=6 > Silence=1）。置信度取两者**较低**的（合并意味混合了两种判断，用最高会掩盖不确定性）。<br>总护栏：剪超 `MaxTotalDropRatio` 就按把握从低到高丢弃 |
| **`FinalScriptBuilder.cs`** ★ | 「转写稿 ∩ 裁剪决策」算成成片口播稿。**纯算术，零 AI** | ★★ **最容易搞错的一件事：剪掉停顿 ≠ 剪掉话**。实测 277 句/184 块的项目，剪掉的 228 秒里 151 秒是静音、60 秒是重录、剩下不到 20 秒才是真删了话。所以"句子的时间范围被块边界切到了"**根本不能**说明这句被截断（按那个口径算，61% 的句子都会被误报）。<br>正确口径只有一条：**这句被剪掉的时间有多长**（阈值 `TruncatedGapSec=0.8s`，误报从 61% 降到 3%）。<br>三个细节：① 必须按块在成片中的先后排（理由见上文）；② 跨块的句子合并成一行（这些块在成片里首尾相接，中间剪的是停顿）；③ 有词级时间码就按词拼文本 |
| **`ShotSplitter.cs`** | 把成片口播稿切成镜头 | 三种切法（用户选）：<br>**(a) 一句一镜**（细分场景可选，**2026-10-01 起已不是默认**）——最自然，但长句会十几秒不换画面<br>**(b) 固定节奏 + 吸附句边界**——默认 6 秒一镜，但**切换点一律落在某句话说完之后**，绝不切在半句中间<br>**(c) 语义合并 ★ 默认（2026-10-01 起）**——贪心把相邻句并成 5~9 秒的语义块，切点恒落句末；块首即超长句（≥max）独自成块；尾部凑不满则并成一块。<br>★ 实测取代"一句一镜"（219 镜平均 1.67s 太碎）<br>★ **V1.10.13：`Split()` 返回前必须调 `FillToTimeline()` 铺满整条决策轴** —— 块尾不再取"这句话说到哪"，改取"**下一块的第一句话从哪开始**"，句间那口气归前一块。理由：行是"点状"的，气口不属于任何一行，落在**块边界**上就整段丢失（实测 26 镜短 **1.340s** = 片头前导 0.560 + 边界留白 0.780 → ⑤ 出片被 drift 自检拦下）。**只动时间窗、不动 `SourceSec` 区间**（ID 靠源区间继承，所以重切不丢 ID）。见 R-20 |
| **`AutoCutOptions.cs`** | 粗剪旋钮（波形层） | 三个预设（保守 0.70s / 适中 0.45s / 激进 0.25s）的每个数字都标了来历——《美的历程》608s 素材、人工剪到 370s 的实测对标数据 |

### 4.6 【媒体 IO `Media\`】

| 文件 | 干什么 | 关键设计 / 踩过的坑 |
|---|---|---|
| **`FFmpegLocator.cs`** | 找到机器上能用的 ffmpeg/ffprobe | 为什么单独抽：三件事都要用（解码给粗剪、渲成片、探测轨道），与其三处各写一遍搜索逻辑然后版本不一致，不如统一。<br>★ **不放死路径**——现在 ffmpeg 在 `D:\HyperFrames\_tools\bin\`，换机器/上 Mac 完全不同。硬编码=换机必炸。顺序：用户配置→环境变量 FFMPEG→PATH→常见位置 |

| **`FFmpegExporter.cs`** | 按 `CutPlan` 导出成片 | ★ 用 `filter_complex` 一条命令跑完，不"先切 N 段再 concat"（零临时文件、只读一遍源文件，实测 307 秒片子 34.5 秒出片 8.89 倍速）。<br>★ Windows 命令行长度上限约 32KB 是真实风险（400 段成功、500 段报"文件名或扩展名太长"）→ 超长自动改用 `-filter_complex_script` 写文件传参。<br>★★ **写文件必须 `new UTF8Encoding(false)` 显式去 BOM**——`Encoding.UTF8` 静态实例会写 EF BB BF，ffmpeg 会把 BOM 当第一行内容，报一个完全看不懂的 `Invalid argument`（错误信息里绝不提 BOM，靠猜猜不出来）。<br>编码器优先 NVENC，失败自动回落 libx264 |
| **`FFmpegAssembler.cs`** ★ | **⑤ 组接：把渲染好的镜头拼成成片**（V1.0.0 主力） | 与 Exporter 分工：Exporter 拿**源素材**裁（源是音频就只能出 m4a）；Assembler 拿**第④步渲好的一堆 MP4**拼接 + 挂上按决策重建的音轨——这才是"渲染完→出成片"那一步（以前缺 B 方案，所以一度只能导 m4a）。<br>**先 `Precheck` 再 `Assemble`**：缺块/音画对不上（>0.5s）直接拒绝，不如先列出缺哪几块。<br>画面：**阶段一**逐块 `ConformOne`（`trim→tpad=clone→trim`）把每块裁/补到该块音频段长度（重编码一次），**阶段二**用 `concat` 解复用器 `-c:v copy` 直拼（不再重编码）。<br>★ 音画对齐 = **音频全程零处理**（不拉伸、不变调、不重采样）；旧的 `asetrate` 微拉伸已废弃（V1.0.4），**别再回去**。<br>★ **V1.10.15 · 插片原声**：`FilmSegment` 多一种段类型 `VideoAudioPath`（= 从渲染产物取音轨，插片勾了「素材原声」时用）。`Assemble` 为每个用到的产物多申请一路 ffmpeg 输入（序号从 2 起：0=画面清单、1=源录音），该路用 `aformat=channel_layouts=mono:sample_rates=<sr>` 统一声道/采样率 —— **源录音是单声道、产物是 aac 立体声，不统一后面那条大 concat 会直接失败**。**音量不在组接层二次施加**（渲染时已按 `data-volume` 录进产物，这里再加一次就是双倍衰减）。<br>★ 立体声用 `pan=stereo|c0=c0|c1=c0` 单位增益复制，**别用 aformat/-ac 2**（走下混路径，实测音量被压低 3dB）<br>写完还落一份 `成片_说明.json` 留痕：几块、设计/实测时长、累积差、拉伸过没有 |

### 4.7 【时间轴逻辑 `Timeline\`】— 精剪编辑器的计算内核

这三个文件都是**纯逻辑 + 零界面依赖**，特意放 Core 以便脱离 UI 单测（拖拽这种交互最容易出边界 bug）。

| 文件 | 干什么 | 关键设计 / 踩过的坑 |
|---|---|---|
| **`AudioPatchLayout.cs`** | "就地重拼"的施工图 | ★ 为什么不能"只把改动那一块重新读一遍"：实测走不通——NAudio 在 m4a 上用 CurrentTime 定位，落点是**随机**的，同一文件不同位置会偏 −168/−512/1998/−2039 个采样（±42ms 且方向不固定）。重读出来的块整体挪几十毫秒，和前后块之间就会"丢一段/重一段"，接缝直接听得出问题。<br>解法：**干脆不读文件**。每块的本质都是「源素材样本 × 增益 × 淡入淡出包络」，上一份拼好的成品里已经存着它了 ⇒ 新值 = 旧值 × (新包络/旧包络)，完全不碰源文件、不涉及定位、几乎不花时间。<br>覆盖日常绝大多数编辑（挪块/裁短/调音量/改淡化/平移/删块）；只有"要更多源素材"（边往外拉、切开、新增块、换源）才需要重读→那时退回整条重拼。<br>唯一数学风险是"旧包络为 0 除不回来"，只有两种情况会为 0（有淡入的第一个样本 i=0；旧增益本身就是 0），看一个点/一个字段就能判定可行性 |
| **`AudioRenderPlan.cs`** | "这条时间轴要渲染成什么音频"的纯数据描述 | 为什么抽离：拼接很贵（开文件/解码/重采样）→ 必须能缓存 → 缓存要有**稳定键**（`Build()` 会算出指纹）。摘录: Fingerprint = 内容指纹，时间轴没变就复用上次拼好的。<br>好处：`Build()` 会把传入的段复制成数组 ⇒ 天生是一份"快照"，界面线程调完 Build 就可以随便改时间轴，后台线程拿这份计划去渲染，不会踩到"集合已修改" |
| **`TimelineCollision.cs`** | 时间轴碰撞求解（拖块时的 mathematics） | 解决"鼠标想放哪" vs "实际能放哪"这两回事。<br>核心概念**空隙（Corridor）**：把其他块占掉的区间挖掉，剩下的连续空白就是走廊。<br>规则：指向的走廊装得下→跟着鼠标（贴墙就是"顶住"）；指向某个块身上→被挤到那块的左/右边缘；装不下→判为无效（画面红警告、松手弹回）；最后一个走廊延伸到 +∞ → 片尾随便放。<br>**坐标约定：全部是时间轴秒数，不是像素**，谁调用谁负责换算 |

### 4.8 【Schema `Schemas\`】

`cutplan.schema.json` / `shotplan.schema.json` / `transcript.schema.json` —— 作为**内嵌资源**编译进程序集，
由 `ContractJson.LoadSchema()` 读出，原文塞给 Agent 当"必须按这个结构输出"的硬约束。
这样 AI 的输出能被程序直接校验，不用靠猜。

## 第七节·五 · ★ V1.13.0「归档」是怎么回事

**一句话**：点「归档」= 整包搬到移动硬盘（`E:\1_创作素材\项目\<项目名>\`，**不分频道层级**），
本地只留一个小桩；项目在工作台里**照旧读得到**，只是读不到原视频、成片这些重件。

**为什么做**：原来的「归档」只改 `project.json` 里一个状态字段、**一个文件都不动**
（原文："归档不会动任何文件，只是把它从「进行中」挪开"）—— 项目越做越多，本地硬盘越来越满，
"归档"两个字名不副实。用户 2026-10-15 拍板：**归档要真的搬，本地要干净**。

| | 内容 |
|---|---|
| **搬到硬盘** | 几乎整包：`project.json`、`script.md`、`stages\` 全套、镜头代码（`.html/.py/.json`）、`素材\`、封面、**成片 mp4**、`export\`、渲染工作区、历史备份 |
| **硬盘不留 · 本地也删** | **分镜渲染出来的画面**（渲染产物里的视频 + `渲染工作区\shots\` 的逐镜片段）、**卡片图**（渲染产物下任意 `images\` 目录）、**渲染器事务残留**（`.shot_xxx.hf-transaction-*`） |
| **本地留（小桩）** | `project.json`（含归档段）、`script.md`、`stages\` 文本（含 `shotlist.json` 分镜稿）、`素材\公共素材\`、封面图、`review\`、`_归档\` |

**判定规则**（改分类只改 `ArchiveService.ScanAndClassify`，别散到别处；**顺序即优先级**）：

1. 渲染器事务残留（路径含 `.hf-transaction-`）→ 两边都不留
2. 卡片图（在 `渲染产物\` 下、路径任一段叫 `images`）→ 两边都不留
3. 分镜渲染出来的画面（`渲染产物\` 下的视频 ＋ `渲染工作区\shots\` 下的视频）→ 两边都不留
4. 历史备份（路径任一段以 `_备份` / `_backup` 开头）→ 搬走、本地不留
5. `review\` / `_归档\` → 强制留本地
6. 文件名带「封面」的图 → 强制留本地
7. 其余视频（成片 / 原声 / 素材）→ 搬走、本地不留
8. `渲染工作区\`（非 `shots\`）→ 搬走、本地不留
9. 其余 **≥ 2MB** → 搬走、本地不留
10. 其余 **< 2MB** → 留本地（桩）

★ **判据宁可保守**：只有"明显是生成出来的逐镜片段"才当可再生的丢掉。`渲染工作区\bodies\` 是镜头的**真源**（HTML，要留），万一里面混了素材视频，那属于不可再生 —— **必须搬走**，不能因为"它在渲染工作区里"就删掉。这就是第 3 条只认 `shots\`、不认整个 `渲染工作区\` 的原因。

★ **别写成死路径**（V1.13.0 发布前自查踩到）：① ② ④ 三条最初写成 `渲染产物\images\`、`_备份\` 这样的**固定前缀**，实测当场翻车 —— 项目里实际存在 `渲染产物\旧219镜\images\`、`_backup_219句\`。凡判据都要按**路径段**匹配，不要用整串前缀比对。

**四条容易踩的（R-22 记录在案）**：

1. **先复制 → 校验 → 才删**。反过来（先删再拷）硬盘一掉线素材就永久没了。
2. **认盘用卷序列号，不是盘符**。盘符会漂（E→F→G），照老路径搬有"搬到别的盘上"的风险。
3. **加 `ProjectModel` 字段必须同步 `ProjectSession.Projected()`** —— 漏搬 = 存一次盘归档信息就没了。
4. **取回时不要用硬盘上的旧 `review\` / `_归档\` 覆盖本地** —— 复盘数据是归档之后还可能继续填的，
   拿归档那一刻的旧版盖回去 = 把后来的记录抹掉。

**归档之后打开项目**：`NavTree.PickLanding` 里有一条最优先判据 —— **已归档的项目一律落「复盘」**，
连"上次停在哪"都不认（上次那页归档后已经没内容可看了）。

★ 原因：本机 PortableGit 的**全局**配置是 `core.autocrlf=true`（检出时会把 LF 变 CRLF），
那会**悄悄改掉源码换行**；所以在 `.gitattributes` 里钉死 `* text=auto eol=lf`，
并在仓库级把 `core.autocrlf` 设成 `false`（双保险）。二进制（ico/png/jpg/wav/exe/dll…）逐个显式标 `binary`。

**日常命令**（在 `D:\工作台工程\工作台` 下执行）：

- [ ] 改了画面相关行为吗？→ 有没有违反「文字锚点」铁律？（禁止零文字镜头）
- [ ] 改了音频链路吗？→ 有没有违反「音频零处理、画面去匹配」？（禁止）
- [ ] 改了 default 路径/参数吗？→ `AppConfig` 与项目 `render-spec.json` 两边都同步了吗？
- [ ] `dotnet build` 是 0 警告 0 错误吗？
- [ ] 在 [`更新日志.md`](更新日志.md) 记一笔了吗（改了什么 / 动了哪些文件 / 为什么）？
- [ ] 这次改动**提交进本地 git** 了吗？（`git add -A` → `git commit -m "一句话说清改了什么"`。
      ★ 养成"一个小功能一次提交"的习惯 —— 这是有了 git 之后唯一的实际收益来源。
      提交前先 `git status` 扫一眼，别把不该进的（临时文件/构建产物）一起端进去）
