远景规划 · 从「剪音频」到「从写到片」

你提的三件事（md 写作 / 分段录音 / 数据与看板），不是三个功能，是一条主线上的三段—— 它们合起来会把工作台从「处理已录好的音频」，变成「从一张空白稿子长出成片」。 本规划给出：这条线怎么走、先走哪段、以及哪一段我建议先别走。

写作台建议最先做 · 零风险 · 即使录音不做也不白做
录音台收益最大 · 但听感有风险 → 先花半天验一次
产能看板有价值 · 但要等前两步数据稳定才有意义
甘特图 / OKR建议不做 · 一人团队用它是仪式感 > 价值

01最关键的一个判断：写的一段 = 录的一片 = 出的一个镜

如果做成「工作台里塞个 md 编辑器」+「再加个录音按钮」两个独立功能， 必然掉进经典同步地狱：稿子改了、录音对不上、镜头跟着错位。 正确的做法是——它们是同一份数据的三种视图，共用一套段落节点。

文稿视图

你在这写
第 3 段 · 2 句
「所以问题不在于……」

录音视图

你在这录
seg_03.wav
18.4 秒 · 录了 2 遍

镜头视图

下游认这个
shot_03.mp4
画面 18.5 秒（含安全尾）

★ 这条链最大的好处是局部重做：改第 3 段的稿子 → 只重录 seg_03 → 只重渲 shot_03， 其余 50 镜一个字节都不动。 而现在改一句台词，得重走「转写 → 粗剪 → 精剪 → 分镜 → 渲染」整整一圈。

02分段录音真正的价值：不是「省事」，是「删掉一整环」

你的说法是「录完就是很完整、且语义切割精确的音频」——对，但更大的收益在别处： 台词不再经过 ASR 那条最脆弱的路。

老路（录音驱动） · 现在走的就是这条
整段录音一口气念完
→
ASR 转写外包 · 要联网
→
粗剪按时间戳删废话
→
精剪切成 184 段
→
分镜51 镜
→
渲染 / 组接出片

⚠ 脆弱点在「转写 → 粗剪」：时间戳靠 ASR 给，实测「原始 ASR」与「整理成稿」差了 56 秒—— 整条下游的时间轴都押在这一步上。

新路（文稿驱动） · 分段录音开启的这条
写稿 md台词即原文
→
分段录音一片 = 一段
→
分镜天然对齐
→
渲染 / 组接出片
① 转写整环消失台词就是稿子原文，不需要 ASR、不需要外包、不需要联网
② 粗剪降级废话根本没录进去，不用听一遍再删
③ 时间戳零误差每段起止 = 片段边界，56 秒那个坑直接不存在
④ 精剪变拖顺序片段本来就是切好的语义单元

03动手之前，先花半天验一件事：分段录音的听感能不能接受

这是整份规划里我最想让你先做的一步，不做这一步，后面两千行代码可能白写。

一段一段录，段与段之间的「气口」是断的——听上去容易变成朗诵，而不是说话。 而读书博主的观众买的恰恰是那种娓娓道来的语感。这是这套方案唯一可能致命的代价， 而且只能实测，不能凭猜。

怎么验（用手机或现有麦克风就够，半小时出结果）
① 从《思辨与立场》稿子里挑 10 段（连续的一小段）
② 一段一段录，录不好就重来
③ 原样拼起来，不做任何后期
④ 戴上耳机，从头听一遍
听不出接缝 → 方案成立，按路线图开工
明显「一顿一顿」 → 先试三个补救，再判：
· 段尾留 200ms 气口（录完别立刻停）
· 段首给 1 秒预备音（找状态）
· 接缝加 crossfade（T-03 那个还开着的决策项，正好在这里派上用场）
补救完还是别扭 → 那就不做「一句一片」，改做「连录模式」：一口气录 3~5 段再切， 只在段间打标记（不真停）。听感＝老路，精度＝新路。

04粒度是这个设计的开关：别一句一片，会录到崩溃

「一段话一录音」里的「一段话」到底多大，决定了这套东西是神器还是刑具。 这个数字必须在动手前定死。

粒度10 分钟稿录起来重录代价听感
一句一片~90 片 极累，每片都要起状态最小（重录 1 句） 最差
句群一片 ★~30 片 可接受中（重录 2~4 句） 较好 推荐默认
自然段一片~12 片 轻松大（错一字整段重来） 最好

★ 建议：默认 2~4 句 / 15~25 秒一片，录音台里给一个滑块现场调， 允许同一篇稿子里不同段落用不同粒度（难念的段拆细，顺的段录长）。

05路线图：五期，按依赖排，不是按兴趣排

  1. 期零 · 听感验证（半天，不写代码）
    就是第 03 屏那件事。这一步决定后面四期怎么走，甚至走不走。
  2. 期一 · 写作台（md 编辑器）· 约 1500 行 / 2 天
    ★ 独立于录音，先单独可用：写完导出稿子，照着念，走老路—— 这样即使录音那条路最后没走通，写作台也完全不白做（它已经解决了「台词经过 ASR 失真」的问题）。
    落点：NavTree 项目内加一页（注释里早就预留了「写作台」这个词）； 数据 项目\script.md + script.json（段落节点带永久 ID，复用现有 ID 血统机制）。
  3. 期二 · 录音台（分段录音）· 约 1200 行 / 2 天
    NAudio 采集 + 实时波形 + 一片一存 seg_<id>.wav + 重录即覆盖 + 粒度假滑块。
    ★ 与写作台共用同一份段落节点，不另起一套数据。
  4. 期三 · 新流水线贯通（文稿驱动）· 约 900 行 / 1.5 天
    让 ①②③ 走新路：跳过转写与粗剪，片段列表直接进分镜。
    ★ 老路必须保留——立项时选「录音驱动 / 文稿驱动」，《思辨与立场》是按老路做的，不能变孤儿。
  5. 期四 · 产能看板（不是甘特图）· 约 800 行 / 1.5 天
    见下屏。数据取自全链路留痕文件，要等前三期稳定才有意义。
  6. 期五 · 素材复用库 / 发布回流 / 目标追踪（按需，可拆开做）
    见第 07 屏。

06关于甘特图和 OKR：一盆冷水，和一个更好的东西

甘特图解决「谁在什么时候做什么、会不会撞车」，OKR 解决「团队目标对齐」—— 这两件事都以「有多个人」为前提。你是一个人：不存在撞车，也不需要对齐仪式。 而且它们要维护的数据量很大（每条任务填开始 / 结束 / 依赖 / 进度），最后会变成新的负担。

但「看板」这个直觉是对的，只是该看的板不是抄来的框架，而是从你自己的数据里长出来的：

指标为什么别人算不出来
每支片的总耗时
立项 → 出片，拆到每一环		 只有工作台握着全链路的时间戳；别的工具只看到其中一个环节
哪一环返工最多
重渲次数 / 拆合次数 / 重录次数		 ★ 这是独一份的。市面上没有任何工具知道你「这一镜渲了三遍」——而这正是最该被看见的浪费
单镜渲染成本
耗时 + 失败率 + 电费		 渲染留痕本来就落在 stages\04-render\ 里，只是从没被汇总过
项目水位
卡在第几步、卡了几天		 现有 project.json 里就有，缺的只是一个视图

★ OKR 如果真想要，做成「年度目标的轻量追踪」就够： 今年出 50 支片 → 现在 18 支 ▓▓▓░░ 36%，一条进度条拉到底。 不要做成任务依赖图，那是给自己找活干。

07你没提、但完整工作台该有的（按性价比排序）

缺口说明性价比
镜头模板库 现在每支片全部从零渲染，但片头 / 片尾 / 转场 / 背景其实是可以跨项目复用的。 攒一个「片段银行」，渲染费能省下一大块 最高
发布物料 片子出了，还要标题 / 简介 / 封面 / 标签。这是同一支片的另一半， 现在完全在工作台外面做 高
项目快照 现在只有「交接前备份」一处。应该有项目级「回到三天前」的能力 中
数据回流 发出去之后的播放 / 完播率能不能回到工作台，反哺选题？ 这是闭环最后一公里，但依赖平台接口，不确定性强 中（但风险高）
多规格导出 竖屏你不做的（已定），但封面图、方版裁剪还是要的 低

08风险与代价（先说丑话）

风险等级缓解
分段录音听感变朗诵致命 期零先验；补救三招（气口 / 预备音 / crossfade）；兜底是「连录模式」
录到崩溃（心理负担）高 粒度默认句群不默认单句；允许连录；允许同一篇用不同粒度
老项目变孤儿高 两条路并存，立项时选模式，不做替换式升级
写作台做成孤岛高 ★ 必须与录音台共用同一份段落节点，否则必然出现「改了稿对不上音」
麦克风还没买— 期一（写作台）不依赖麦克风，现在就能做；录音台等你买了设备再做，顺序正好
看板数据不准低 等前三期稳定后再做；指标全部从既有留痕文件算，不另建数据源

09等你拍板的四件事

  1. 先做期零的听感验证吗？半天，不写代码。我建议做——它能省掉几千行可能白写的代码。
  2. 写作台放项目内还是全局？我倾向项目内（稿子属于某一支片，跟流水线在一起），但你想拿它当通用笔记的话就放全局。
  3. 录音的粒度默认值我推荐 2~4 句 / 15~25 秒。你录过自己的稿，体感更准。
  4. 甘特图 / OKR 还做吗？我的建议是：不做甘特图；OKR 降级成一条年度进度条。你坚持要的话我照做，但会把工作量如实报给你。
