## 0. 一句话

> 把「归档」从"**只改一个状态字段、零文件移动**"升级为
> "**整包搬到移动硬盘 + 本地留小桩**"，
> 并同时建一条**与归档完全解耦**的复盘数据链路，为将来的数据可视化留好接口。

**今天的「归档」是什么**（源码 `ProjectListView.xaml.cs` 原文）：
> 「归档不会动任何文件，只是把它从「进行中」挪开。」

改造后它会真的搬文件。

## 1. 归档：点下去之后发生的六件事

| 步骤 | 做什么 | 失败怎么办 |
|---|---|---|
| ① 探盘 | 按**卷序列号**认移动硬盘（写进 `config.json`，记一次） | 盘不在 → **拒绝并提示**，不做任何动作；不排队、不静默跳过 |
| ② 门槛 | 项目必须**有成片**（`stages\05-assemble\` 里有成片 mp4） | 按钮灰着，鼠标悬停说明原因 |
| ③ 确认 | 弹**清单**：搬走 XX 文件/XX MB、删本地 逐镜 mp4 XX 个 + 卡片图 XX 张、保留 XXX、目标路径 | 取消 = 什么都不做 |
| ④ 复制 | 整包复制到 `E:\1_创作素材\项目\<项目名>\`（**无频道层级**） | 中途掉盘/出错 → **立刻中止，一个都不删** |
| ⑤ 校验＋删 | 逐个校验指纹 → **全部通过 → 才删本地大件** | 有一个对不上 → 中止，已删的从 E 盘回拷 |
| ⑥ 入台账 | 调总库现成的 `update_ledger.py` 增量入库（文件层） | 后台跑、带进度、**可跳过**，不卡归档动作 |

★ **顺序铁律**：先复制 → 校验 → 全过 → 才删。绝不"边搬边删"。

## 2. 搬什么 / 删什么 / 本地留什么（核心）

| | 内容 |
|---|---|
| **搬到 E 盘**（归档终点） | `project.json`、`script.md`、`stages\` 全套、渲染产物里的 **`.html` / `.py` / `.json`**（镜头代码）、`素材\`、封面、**成片 mp4**、`export\` |
| **E 盘不留 + 本地当场删** | **逐镜 mp4 / silent.mp4**、`渲染产物\images\` 卡片图、`_备份\`、`渲染工作区\`、`media\` 里的大视频 |
| **本地留（小桩，原地瘦身）** | `project.json`（基础信息＋归档段）、`script.md`、`stages\` 全套文本（**含 shotlist.json 分镜稿**）、`素材\公共素材\`、`封面\`、`review\` |
| **从来不留** | 任何渲染出来的视频（逐镜） |

★ 判据一句话：**"镜头渲染出来的画面"删，"能重渲出它的代码/封面/脚本"留。**
★ 成片**留**——它是作品，不是镜头。

**本地桩放哪**：就在原位置 `D:\工作台\项目\<项目名>\`（原地瘦身）。
理由：工作台靠扫 `项目\<文件夹>\project.json` 认项目，桩留在原地 → **工作台零改动就能读到**。

## 3. 复盘链路（与归档解耦）

- **位置**：项目内新增独立导航页 **「复盘」**（排在"组接导出"之后），**进行中 + 已归档都能进**。
- **字段**（沿用已有《数据复盘页-细化方案》8 项）：
  `平台` / `发布日` / `统计日` / `距发布天数`
  ＋ `播放` / `完播率` / `点赞` / `涨粉` / `收藏` / `评论` / `转发` / `主页访问`
- **结构**：**多平台 × 多次快照**（时间序列）——为将来画趋势线留好形状。
- **落盘**：`<项目>\review\review.json`（**本地权威**，硬盘不插也能读）＋ `<项目>\review\复盘报告.md`
- **本次只做**：录入 + 本地存档 + 一屏看结果。
- **本次不做**：图表 / 趋势线 / A/B 对比（留给"将来做数据可视化"）。

★ **关键约束（用户强调）**：复盘**不绑定归档**。没归档能填，攒几个项目一起处理也行，
因为硬盘不一定随时插着。

## 4. 归档之后，工作台里看到什么

- 打开已归档项目 → **直接落到「复盘」页**（剪辑页打不开，没必要打开）。
- 页面顶部一条归档说明条：`本项目已归档于 2026-10-15，工程在 E 盘`。
- 下面照常看/改数据与复盘记录。
- 两个按钮：**「取回工程」**（从 E 盘整包拷回来）、**「打开归档文件夹」**。
- 卡片上原来的「恢复」按钮 → 改成 **「取回工程」**（取回成功 → 状态自动回到进行中）。
  → 取消"点一下就取消归档"这种半吊子操作。
- 工作台**仍能读到**：基础信息、立项时间、归档时间、复盘记录、自媒体数据。

## 8. 决策记录（本轮敲定的全部结论）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 搬还是复制 | **真搬走**（本地只留小桩），目的是本地硬盘清爽 |
| 2 | 本地留什么 | 基础信息 + 归档信息 + 复盘数据 + 报告 + 封面小图 + **分镜稿（纯文本小）** |
| 3 | 删什么 | **只删分镜渲染出来的画面**（逐镜 mp4）；成片留 |
| 4 | E 盘目录 | 沿用项目自己的结构，**不要频道层级** → `项目\<项目名>\` |
| 5 | 数据接口 | 8 字段，多平台×多次快照；**本地为权威** |
| 6 | 范围 | 只做工作台项目这条链路；散装文件不动 |
| 7 | 认盘 | 按**卷序列号**；盘不在拒绝 |
| 8 | 台账 | 文件层走 `update_ledger.py`；项目层**不进库** |
| 9 | 回滚 E 盘两份 | 移到 `E:\_回收\`，5 个独有文件先保回 D 盘 |
| 10 | 取回 | **做**（取回工程 + 打开归档文件夹） |
| 11 | 做到哪 | 最小**但完整**的通路：录入＋存档＋看结果；图表不做 |
| 12 | 门槛 | 至少要有成片 + 二次确认；**复盘不绑定归档** |
| 13 | 数据落点 | 项目自包含（`project.json`＋`review\`），可视化时扫目录聚合 |
| 14 | 归档后打开 | 落「复盘」页 + 说明条 + 取回按钮；原「恢复」→「取回工程」 |
| 15 | 复盘入口 | 项目内独立页，归档前后都能进 |
