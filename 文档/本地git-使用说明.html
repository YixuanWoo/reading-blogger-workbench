源码工程从此能「存档、回退、看每步改了什么」· 2026-10-15

一句话：给你的源码工程装了一台"时光机" —— 每次改完存一档，以后任何一步都能翻回去看。
仓库就在工程夹里（`D:\工作台工程\工作台\.git`），单机本地、不上传任何地方。 已存了 2 档：一是全工程的起点，二是刚才那批文档改动。

1最该看的一个数：它有多"轻"

你担心的是"体积越来越大"，这件事正好解决的就是它

东西大小
工程文件夹（含编译产物，实际占硬盘）198 MB
真正的源码（进 git 的部分）3.2 MB · 277 个文件
git 自己的仓库（.git）2 MB

★ 差在哪？那 190 MB 全是编译产物（bin / obj） —— 每次编译都会重新生成， 存进 git 没有任何意义，还害你每次编完都看到"一堆好像改了什么"的假消息。已经排除掉了。

2我替你做的三个决定

决定为什么
排除编译产物
（bin / obj / 日志 / 缓存）		 不排除的话仓库会胖 30 倍，而且每次编译都冒一堆"什么都没改"的假改动 —— 那 git 就废了，你会不想看它
钉死"换行符"不许乱动 你这台机器上 git 有个默认习惯：会把文件里的换行悄悄换一种写法。那样每次它碰过的文件都"整篇都改了"，diff 完全没法看。已经关掉这个习惯
把 4 个文件统一成同一种换行符 工程里 214 个文件是一种，唯独 4 个（早期 VS 自动生成的）是另一种。一个仓库混两套，以后看改动会整篇乱跳。只动了换行符，一个字的内容都没改（其中两个原本自带 BOM，也原样留着）。改完已重新编译：0 警告 0 错误

3你怎么用（就三个动作）

打开"命令提示符 / PowerShell"，先进入工程夹：cd /d D:\工作台工程\工作台

# ① 看：现在改了什么 git status # ② 收：把这些改动放进"待存档" git add -A # ③ 存：存一档，一句话写清这次改了啥 git commit -m "修好了某某问题"

后悔药（想退回某个文件、看看历史）：

# 看最近存过的 10 档 git log --oneline -10 # 看某次改动具体动了哪些行（还没存档的时候用） git diff # 把某个文件退回"上次存档"的样子（★ 会丢掉这个文件现在的改动） git checkout -- 文件路径

★ 一条经验：一个小功能存一档。别攒一星期存一次 —— 那样出了问题也不知道是哪一步搞坏的。

4必须说清楚：它不做什么

❌ 它不是备份

  • 仓库就在你**同一块硬盘**上
  • 硬盘坏了，代码和仓库一起没
  • 真要备份得另存一份到别处（移动硬盘/网盘）

✅ 它管什么

  • "这行代码什么时候改的、为什么改"
  • 改坏了能一步退回上一版
  • 同时做两件事、想对比着看

★ 还有一条：它只管源码工程。你的 D:\工作台\项目\（视频项目数据）不在里面，也不该在里面 —— 那是素材数据不是代码，混进来会把仓库撑爆。
