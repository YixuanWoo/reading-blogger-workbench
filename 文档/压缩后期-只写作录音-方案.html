流程优化方案 · 未动代码

把后期压到只剩「写作 + 录音」

目标是你说的那句：我只负责内容，产出和包装全归 Agent。

关键不在"让机器剪得更聪明"，在于让"剪"这件事消失。
钥匙是你已经写好的那份稿子 —— 它是标准答案。
而且这条路排队顺序要改：最该先做的不是录音台，是「对稿」和「品控」—— 它们不花钱、不买设备、没有未知数。

1先把账算清：10 个环节，你其实只碰 4 个

你抱怨"太啰嗦"，是因为这 4 次动手分散在整条链上，每次都要重新进入状态。

#环节现在谁做目标谁做
1写作你你（不变，这是你的核心价值）
2录音你你（不变）
3转写外部 Agent消失 —— 稿子就是转写
4粗剪工作台代码猜对稿，只标真偏差
5精剪你（逐条审，最痛）消失 / 只剩几条争议
6分镜设计AgentAgent（不变）
7渲染AgentAgent（不变）
8组接出片工作台自己不变
9品控你逐镜看Agent 自动查 + 自动返工
10终审你逐镜看你 —— 但只看一份异常报告

你的动手次数：4 次 → 2 次，而且剩下这 2 次都在最前面（写作、录音），不用来回切换状态。

2★ 为什么"代码粗剪"永远让你不满意

根因不是算法差，是信息不够。我去读了 AutoCutEngine，它其实已经很强了。

它跑的是两轨六层：波形轨抓静音气口 + 波形级重复；文本轨抓填充词（嗯/啊/这个）、半截重说、词级口吃、整句重复。

它会发现"你说了两遍"—— 但它不知道哪一遍是你想说的。

打个比方：这是老师改作文，手里却没有标准答案。他只能凭语法猜"这两句重复，划掉一句"—— 对错全看运气。

要判什么现在（只有录音）有了稿子之后
说了两遍，留哪遍 只能猜（一般默认留最后一遍） 哪遍跟稿子对得上，就留哪遍
这句是不小心说的，还是本来就要说 判不了 稿子里一查就知道
哪里该断句、该切镜 靠静音时长猜 稿子的段落和句子就是天然边界
时间轴准不准 ASR 猜的（历史上差过 56 秒） 文本已知 → 时间戳只落在你真正说了的那一段里，不漂

而你手里早就有那份标准答案了 —— 就是写作台里的 script.md（V1.11.x 已落地）。只是现在没人把它交给粗剪。

3三个新方案，分别干掉一个痛点

A · 对稿 —— 干掉「精剪」新想法 · 最该先做

像演戏前对台词：拿你写的稿子，去校对你的录音。

怎么走说明
输入script.md（你写的）+ 现有的 ASR 转写稿
处理逐句对齐 → 找出「重说了 / 卡壳了 / 漏了 / 多说了 / 顺序换了」
输出 ①偏差清单：每条带类型 + 位置 + 建议动作
输出 ②修正后的时间轴（比 ASR 猜的更准）
产物格式★ 仍然是 transcript.json → 下游 ②③④⑤ 一行代码都不用改

偏差分两类：明确的（重说、卡壳、口误、稿子里没有的多余话）→ Agent 直接处理，不问你；有争议的（整句漏了？顺序换了？删了会不会断意思？）→ 推给你，通常是个位数。
★ 于是"精剪"从逐条划 200 条变成看 3 条。

为什么它比"分段录音"更该先做

分段录音能带来同样的收益，但它要买麦克风、要改掉你的录音习惯、还有一个致命未知数 —— 听感会不会变朗诵（远景规划里的"期零"就是要验这个）。
而对稿这三样全都不需要：用你现在的整段录音就够了，零风险、零设备、零习惯改动，却能直接干掉最痛的精剪。

工程上有个好消息：相似度比较的轮子已经在了（TextSimilarity.cs，已有 Dice / Overlap / LcsRatio / PrefixLen 四把尺子）—— 对稿正好要用它。只对新项目生效，老项目（思辨与立场这类没写稿的）完全不动。

A′ · 答疑：「说话跟稿子不一样」会不会让对稿失效？2026-10-08 补

不会 —— 前提是把目标从「精确」换成「够用」。对稿不是校对。逐字比对那叫校对；对稿做的是顺序对齐：把稿子的段落和录音的时间段按先后顺序连起来。你换了词、加了话、绕了弯，只要大方向还是照稿子讲的，这条线就断不了 —— 而你是对着自己的稿子讲，顺序几乎总成立。

整条下游没有一个环节需要「逐字精确」：你不出字幕条，所以最难的「每个字落在哪 0.01 秒」这一档，压根不在需求里。实测分档：

精度档是什么要不要
① 顺序你大致按稿子的先后顺序讲要（几乎总成立）
② 段级这段话对应稿子哪一段要（分镜靠它划边界）
③ 句级这一句对应稿子哪一句要（精剪靠它认「哪遍才是你要的」）
④ 词级每个字精确落在哪 0.01 秒不要（不出字幕条）

★ 反直觉的好消息：口语化反而让对稿更强。
今天的自动粗剪靠「词像不像」找重复（TextSimilarity 那四把尺子）—— 你要是改着词重说一遍（头一遍「这个很重要」、第二遍「这点特别关键」），词面对不上，它就认不出这是同一句，重复就漏过去了。
但在对稿里，这两遍都会对到同一段稿子 → 重复自动暴露。你越爱换词，对稿相对今天的优势越大。

那什么时候会真的失手？—— 稿子里压根没有、你临场整段加的话；那里给不出锚点。所以做法是加一道可信度门槛，分三档走：

对齐结果怎么认出来的怎么办
对上了词面 / 顺序都对得上自动采用，不问你
说岔了换了词，但顺序和长度还像列出来，你扫一眼
稿子里没有前后都对不上，疑似临场发挥退回今天的纯音频做法，不硬套

★ 设计原则就一句：对稿最差不能比今天差。认不准就退回去，绝不硬套 —— 所以它的下限 = 今天的水平，上限 = 替你看掉大部分精剪。

★ 附带红利：对稿跑几次，它会统计出「你总把 A 说成 B」。这些正是你「写起来顺、念起来别扭」的词 —— 顺手改回稿子，稿子会自己进化成口播友好版。也就是你说的「有些词写的时候顺畅、口播时未必适合」，它正好替你圈出来。

★ 工程实现要点（工业界标准做法，别自己发明）：长稿 × 长录音要按静音切段、再逐段对齐，别整篇一次对齐 —— 否则一处错位会把后面所有时间戳一起带偏（这就是「强制对齐」最经典的坑）。每段单独算可信度，低于阈值就标记或退回。参考：广电字幕生产线（Qwen3-ForcedAligner 落地）、有声书文本对齐工程 —— 核心做法都是「分段 + 置信度 + 低置信标记复核」。

★ 好消息：你说的「保后不保前」，引擎里已经埋了雏形

读了 RepeatDetector.cs 和 SpeechIssueDetector.ScanRetakes，两处都已经按「保留后一遍」在做，只是判据还不够强：

层现在怎么判缺什么
波形层
RepeatDetector		后一遍不比前一遍短（比值 ≥ 0.95）→ 剪前一遍；否则只提示、不动手只看时长比，两遍说得不一样（改词重说）就认不出
文本层
ScanRetakes		把前一遍标成废片；护栏 = 后一遍短于前一遍 0.70 就不删只比「两遍彼此像不像」，没有第三方参照

★ 这两个缺口正好被两样东西补上：① 稿子 = 第三方参照（改词重说也能认出来）；② 「两遍都完整就降置信」= 给无条件的「保后」加一道刹车。
所以对稿不需要大模型 —— 对齐是成熟算法（序列对齐），取舍是纯规则，只有少数低置信点交人复核。

★ 澄清：「对完稿子，音频就自动出来了？」—— 一半对

问的是答案
剪好的干净录音基本是自动的 —— 对稿输出的是「决策」（留哪段、剪哪段），按决策裁源音频是全自动的，你只看被标记的少数点
整条成片不是 —— 后面还有 ④ 分镜 → ⑤ 渲染 → ⑥ 组接，三步已经自动化（Agent + 工作台）但不能省，它们决定画面

★ 所以对稿吃掉的只有「精剪」这一段人工。你要的「我只写作录音」能到的位置是：你写作、你录音、你看一遍成片；中间的剪辑 / 分镜 / 渲染 / 组接全自动。

★ 代码佐证：AutoCutEngine.cs 头部原话就是「为什么输出的是"决策"而不是"新音频"」—— 粗剪这一环从来不产出音频，只产出「怎么剪」。

B · 品控清单化 + 自动返工 —— 干掉「逐镜核对」新 · 但已有基础

"品控全交给 Agent"要成立，必须先有一份可机检的清单。判据分三档：

档判断怎么办
绿灯 时长 · 分辨率 · 帧率 · 有没有声音 · 音画同步 · 黑帧 · 静音段 · 镜号对不对 · 有没有溜进字幕条 机器全查，你一个字都不用看
黄灯 每镜有没有文字锚点 · 画面里的字对不对（OCR）· 内容贴不贴题（语义比对）· 听感节奏 列出来，你扫一眼
红灯 好不好看 · 情感到没到 · 这个转场是不是俗 · 节奏对不对 只有你能判

★ 所以准确的说法是：Agent 负责把"错的"全部抓出来，你只负责判断"好不好"。
它不是替代你的审美，是替代你的逐项核对。

已有基础（不白做）：视觉规范.md 已外部化并注入提示词（T-26 ①，V1.11.3）→ 改画面标准 = 改一个文本文件；成片审片台（T-27，V1.12.0）已打通"打点 → 唤醒 Agent 批量重渲 → 重新组装"这一圈。
缺的是：① 把散落各处的判据收成一份清单（现在它们是"避免出错的手段"，不是"一份能跑的检查表"）；② 清单里能机检的部分自动跑，不合格自动发重渲，不用你打点。

C · 异常报告 —— 干掉「逐镜看片」新

终审从"把片子从头看到尾"，变成"看一页报告"：

灯报告里怎么显示你的动作
绿折叠起来，只显示一行汇总（如"34 镜合格"）不用看
黄展开，附抽帧缩略图 + 具体问题扫一眼，点"通过/重做"
红置顶，附原因 + 一键"重渲这一镜"处理，然后重看这几镜

重渲这条路已经通了（单镜重渲 + 永久 ID + 产物指纹判"待重渲"），所以闭环是：品控标红 → 点一下 → Agent 重渲 → 自动复查。

4★ 排队顺序要改：把「对稿」和「品控」提到录音台前面

远景规划里的顺序（写作台 → 录音台 → 贯通）是按方案完整性排的。按你最痛什么排，顺序不一样。

★ 这么排的理由：第 4 步有两个硬前置（买麦克风 + 验听感），第 5 步依赖第 4 步；而第 1~3 步什么都不等，却能拿走你最痛的两件事。先做能做的，别让整条路卡在一个未知数上。

5诚实说：有三件事压不掉

把边界说清楚，比许诺一个到不了的目标有用。

压不掉的为什么
